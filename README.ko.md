# dart-review-agent

**상태: 진행 중 (README 초안, 2026-10-08).** 아래 결과는 직접 쓴 개발용 질문으로 잰 것이다. 봉인된 사전 등록 평가는 아직 하지 않았다. 영어판: [README.md](README.md).

"삼성전자 2025년 매출액이 전년보다 얼마나 늘었어?" 같은 질문에 OpenDART 재무제표로 답하는 로컬 도구다. 비교가 성립할 때만(같은 연결·별도 기준, 같은 기간 길이, 같은 통화, 설명되지 않은 재작성 없음) 기간을 비교하고, 아니면 거절하거나 되묻는다. 보여 주는 재무 수치는 모두 검증된 도구 결과에서 나온다.

```text
$ python -m dart_review demo        # 인증키, 모델 서버, 네트워크 없이 실행
## 삼성전자 매출액
**검증 상태:** 비교 가능
| 구분 | 기준 | 기간 | 금액(원) | 보고서 | 접수번호 |
| 비교 기간 | 연결 | 2025년 연간(1~12월) | 333,605,938,000,000 | 2025년 사업보고서 | 20260310002820 |
| 기준 기간 | 연결 | 2024년 연간(1~12월) | 300,870,903,000,000 | 2025년 사업보고서 | 20260310002820 |
**변화:** 32,735,035,000,000원 (10.88%, 증가)
```

## 보기보다 어려운 이유

OpenDART의 같은 칸이 보고서와 재무제표에 따라 다른 뜻이다. 캐시한 보고서 72건으로 확인했다([데이터 확인 기록](docs/DATA_NOTES.ko.md)).

- 분기 손익계산서의 `thstrm`은 3개월인데, 분기 현금흐름표의 `thstrm`은 이미 연초부터의 누적이다.
- 분기 재무상태표의 "전기"는 전년 같은 분기말이 아니라 **전년 말**이다.
- 나중 보고서가 앞 값을 **재작성**한다(카카오, 셀트리온). 카카오 2024년 3분기 매출 증감률은 재작성 값 기준 −4.48%, 처음 공시 값 기준 −11.08%다.
- 계정ID가 틀린 경우가 있다. 카카오 2023년 분기 매출은 `ifrs-full_GrossProfit`으로 표기돼 있다.

이 규칙들은 모두 코드이고 실제 캐시로 테스트한다. 규칙을 순진한 버전으로 바꾸면 해당 함정 테스트가 실패하는 것도 확인했다(11개 중 11개 검출).

## 동작 방식 (교차 확인형)

```text
질문 ──► 키워드 규칙 ──► 해석 A ─┐
     └─► 로컬 모델   ──► 해석 B ─┤ 같은가? ── 예 ─► 도구(규칙이 OpenDART 데이터를 판정) ─► 코드가 답을 씀 ─► 숫자 검사 ─► 답
                                 └ 아니오 ─► 두 해석을 보여 주고 어느 쪽인지 되묻는다
```

- 두 해석자가 각자 질문을 읽는다. 키워드 규칙과 로컬 모델(Ollama의 `gpt-oss:20b`, 해석 JSON 요청 1회, 프롬프트에 기준 날짜 포함)이다. 둘이 같으면 코드가 답하고, 다르면 되묻는다. 두 해석기는 같은 저자가 같은 기본값 표로 만들었으므로, 오류가 서로 독립이라고 보장하지는 않는다.
- 한쪽만 읽은 경우:
  - 모델 해석을 얻지 못하면 **답하지 않는다.** 규칙만으로는 답하지 않는다(규칙은 표현 변형 p06을 확신 있게 틀렸다).
  - 규칙이 못 읽고 모델만 읽으면(예: 연도 없는 "작년 매출", "순익") 코드가 쓴 "이렇게 이해했습니다: …"를 맨 앞에 두고 답한다. 해석이 틀렸으면 사용자가 바로 볼 수 있다.
  - `--no-model`은 규칙만 쓰겠다고 사용자가 직접 고른 모드이고, 답에 그렇게 표시한다.
- 지원하지 않는 계정은 비슷한 계정으로 바꿔 읽지 않고 거절한다. 유동자산(≠자산총계)이나 매출원가(≠매출액)처럼 지원 계정 이름을 일부로 포함하는 계정도 마찬가지다. 거절은 두 해석이 모두 거절일 때만 확정한다.
- 사실 문장(금액, 기간, 기준, 이유)은 모두 코드가 도구 결과로 쓴다. 모델은 문장을 쓰지 않는다.
- 보여 주기 전에 본문과 Markdown 보고서 전체의 숫자를 검사한다. 금액·비율·접수번호는 도구 결과에 있어야 한다. 연도는 도구 결과나 질문에 있어야 한다. 되묻기 문장과 "이렇게 이해했습니다" 문장에서는 해석이 제안한 기간의 연도도 허용한다(해석으로 표시되는 문장이기 때문이다). 근거 없는 숫자가 하나라도 있으면 답을 내보내지 않는다.
- 숫자 검사는 같은 값이 근거에 있는지만 본다. 그 숫자를 어느 기간에 붙였는지, 원인 설명이 맞는지는 보장하지 않는다. 이것은 렌더러 테스트와 사람 검토로 확인한다.

## 여기까지 온 과정 (실패한 시도 포함)

개발 질문 13개와, 비교 실행 전에 써 둔 표현 변형 13개로 쟀다. "최종"은 실행 전에 고정한 기준으로 본문을 1차 검토한 뒤의 점수다. 전체 보고서: [eval/feasibility_2026-10-07/REPORT.md](eval/feasibility_2026-10-07/REPORT.md).

| 설계 | 결과 | 보여 준 것 |
|---|---|---|
| 올바른 도구 결과를 주고 모델이 답 전체를 씀 | 자동 11/13, **최종 1/13** | 구조화된 칸은 맞았지만(숫자 10/10) 본문이 한 단어이거나 기준·이유를 빠뜨림 |
| 에이전트: 모델이 도구를 부르고 결정, 사실 문장은 코드 | 23/26 | 나아졌지만 결정 단계 실패와, 근거 없는 원인을 단정한 해석 문장 |
| 키워드 규칙만 (기준선) | 25/26 | **에이전트를 이김.** 다만 실패 1건이 확신에 찬 틀린 비교 |
| **교차 확인 (현재)** | **25/26, 자신 있게 틀린 답 0** | 기준선의 오해가 되묻기로 바뀜. 26문항에 모델 요청 26회 |

에이전트가 키워드 기준선을 이기지 못해 설계를 바꿨다. 모델을 온도 0.7로 세 번씩 부르는 방식도 시험했지만, 교차 확인이 놓치는 오해를 더 잡지 못했고 비용은 세 배라 채택하지 않았다.

**독립 검토 뒤 수정 (2026-10-08):** Codex 검토에서 세 가지가 나왔다. 모델이 실패하면 규칙 하나로 답하던 경로, 비지원 계정을 비슷한 계정으로 바꿔 읽던 규칙, 검사를 거치지 않던 보고서·되묻기 출력이다. 고친 뒤 같은 26문항을 다시 쟀고, 답과 모델 해석이 모두 같았다(25/26, 자신 있게 틀린 답 0). 점수에 넣지 않는 탐색 질문 13개에서 본 것은 이렇다([보고서](eval/3-0b_2026-10-08/REPORT.md)).
- 비지원 계정 5개는 두 해석이 모두 거절했다.
- 규칙이 못 읽은 질문 가운데 2개("작년 매출", "순익")는 모델 해석으로 맞게 답했다.
- 모델이 1개를 잘못 읽었다("작년 영업이익"을 시점 값으로 읽음). 틀린 숫자는 나가지 않았지만 답할 수 있는 질문을 거절했다.

**이 숫자의 한계:**
- 질문, 표현 변형, 탐색 질문, 규칙, 프롬프트를 모두 한 저자가 썼다.
- 범위가 좁다(회사 3곳, 계정 6개, 2023~2025).
- 모델 결과는 온도 0의 한 번 실행이다.
- 본문 검토는 Claude의 1차 판정이고 사용자 확인 전이다.
- 공정한 검증은 다른 회사 4곳으로 하는 봉인된 평가(로드맵 3-1)에서 한다.

## 빠른 시작

```bash
python -m dart_review demo
python -m unittest discover -s tests
python -m dart_review ask "삼성전자 2025년 매출액이 전년보다 얼마나 늘었어?" --no-model --cache demo/opendart --offline
```

본인 OpenDART 인증키를 `~/.config/opendart/api_key`(권한 600)에 두고, 로컬 Ollama에 `gpt-oss:20b`가 있으면:

```bash
python scripts/fetch_dev_cache.py
python -m dart_review ask "카카오 2024년 3분기 매출은 전년 같은 분기보다 얼마나 줄었어?"
```

Python 3.10 이상, 표준 라이브러리만 쓴다.

## 저장소 구성

| 경로 | 내용 |
|---|---|
| `dart_review/` | 클라이언트와 캐시, 기간·계정·비교 가능성 규칙, 도구, 문장 작성, 숫자 검사, 교차 확인, CLI, 비지원 계정 판별용 계정명 사전(`account_vocabulary.json`, 개발 캐시의 계정명만) |
| `eval/` | 개발 질문과 정답, 채점기, 실행기, 실행 기록 |
| `demo/` | 재생 데모용 OpenDART 응답 축소본과 기록된 모델 해석 |
| `docs/` | 범위, 로드맵, 데이터 확인 기록, 정답 규칙, 평가 설계, 독립 검토 |

## 안전과 재현

- OpenDART 인증키는 `~/.config/opendart/api_key`에서만 읽고 로그·캐시·저장소에 남기지 않는다. 공개 안전성 검사(`scripts/check_public_safety.py`: 키 값, 개인정보, 로컬 경로)를 커밋 절차에 넣었다. git hook으로 강제하지는 않는다.
- 원본 API 응답은 재배포 조건을 확인하기 전까지 저장소에 넣지 않는다(`cache/`는 git 제외). 데모에는 대상 계정 6개의 행만 넣었다.
- 평가용 회사 4곳은 봉인했고 개발 코드는 이들을 조회하지 않는다. 회사를 고를 때 계정 행 수와 계정 이름은 봤고, 금액은 보지 않았다.
- 평가 기준은 매번 실행 전에 커밋했다. 다른 에이전트(Codex)의 독립 검토 세 번을 재현해 반영했다([docs/reviews/](docs/reviews/)).
- 평가 실행(`eval/`)마다 실제 요청, 원시 응답, 모델 digest, 프롬프트·도구·정답의 해시, 기준 날짜(3-0b 실행부터)를 기록한다. CLI `ask`는 아직 요청 기록을 남기지 않는다.
