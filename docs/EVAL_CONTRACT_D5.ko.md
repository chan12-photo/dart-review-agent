# D5 문서 → 엑셀 정확도 평가 계약 (초안 1판, 2026-10-20)

- 상태: **초안 1판. 사용자 결정(8절)과 Codex 검토 전이다.** D5를 할지는 아직 정하지 않았다(계획: [`EVAL_PLAN_D5.ko.md`](EVAL_PLAN_D5.ko.md)).
- **이 계약은 D4 계약 7판([`EVAL_CONTRACT_D4.ko.md`](EVAL_CONTRACT_D4.ko.md))을 그대로 따른다.** 아래에 적은 것만 다르다. D4 계약의 "D4"는 "D5"로, `d4-registered`는 `d5-registered`로, `eval/d4_eval/`은 `eval/d5_eval/`로 읽는다.
- 목적: D4가 찾은 결함을 고친 제품이 **처음 보는 문서**에서 표시 없이 틀린 값·계정명, 가리키지 않은 빠진 칸을 내는지 잰다. 기준은 D4와 같다(텍스트 PDF S1 = L1 = S2 = 0, 합성 스캔 S1 = 0).
- 하지 않는 것: D4 문서로 잰 개발 측정(`eval/documents_2026-10-20_after-d4/`)을 평가 결과로 쓰지 않는다. D4 결과를 바꾸지 않는다.

## 1. 순서 (D4 1절과 같음)

① 계약 → ② Codex 검토(필수) → ③ 사용자 결정 → ④ 고정(F) → ⑤ 후보 판정과 문서 준비 → ⑥ 정답과 매핑표 확정 → ⑦ 등록(R, 태그 `d5-registered` push) → ⑧ 실행 → ⑨ 판정·보고(결과 Codex 검토 뒤 공개).

- ⑥과 ⑦ 사이에 등록 전 Codex 검토를 한다(필수).
- 고정 기록은 `eval/freeze_d5.json`, 등록 기록은 `eval/register_d5.json`이다.

## 2. 대상

- **제품 P:** ④에서 고정하는 커밋. D4 결함 수정(`5cdb4e1`)과, D4 문서 개발 측정 뒤의 수정을 포함한다.
- **평가 도구 T:** ④에서 고정하는 커밋. D4 도구와 다른 점은 3절에 적는다.
- 모델, 프롬프트, OCR, 기계: D4 2절과 같다. ④에서 다시 기록한다. 다르면 다른 대로 기록하고 보고한다.

## 3. 평가 도구의 변경 (④ 전, 이 계약과 함께 Codex 검토)

D4에서 새 문서가 드러낸 도구 결함 두 건을 고친다. 고친 뒤 D4의 저장 기록을 새 도구로 다시 채점해, 바뀌는 칸이 아래에 예상한 것뿐인지 확인하고 그 결과를 기록한다. D4의 공식 결과는 D4의 도구로 낸 것 그대로 둔다.

1. **정답 생성기의 재무제표 찾기:** 다음을 재무제표로 찾는다.
   - 띄어 쓴 제목("연결 재무상태표")
   - 점 날짜 기간 줄("2025.12.31 현재", "2025.01.01 부터 2025.12.31 까지")
   - D4에서는 DSR의 4개 재무제표를 사람이 옮겨 적었다.
   - D4 문서로 확인할 것: DSR에서 사람이 적은 212칸을 생성기가 같게 만든다.
2. **계정명 비교:** 정답 생성기와 채점기가 같은 방식으로 계정명을 다듬는다.
   - 끝에 붙은 글자 없는 표시(" :")는 뺀다.
   - 가운뎃점(ㆍ, ·, ・)은 한 글자로 본다.
   - D4에서 값이 맞는데 L1이 된 10칸(현대모비스 8, 와이솔 2)이 L1이 아니게 되고, 다른 칸은 바뀌지 않아야 한다.
3. **실행기와 집계기의 경로:** `run_d4.py`, `official_d4.py`, `position_check.py`는 D4의 경로(`eval/d4_eval/…`)가 박혀 있다. D5 문서 목록·등록 자리를 인자로 받게 고치고, D4 경로를 기본값으로 둔다. D4 시험이 그대로 통과해야 한다.

## 4. 평가 문서

- **텍스트 PDF:** D4의 모집단과 순서(`eval/d4_population.json`, `sha256("D4-2026|" + 고유번호)`)를 그대로 쓴다.
  - **20번부터** D4 계약 3.2의 절차로 판정해 포함 10곳이 되면 멈춘다. 순서는 D4 때 고정·공개됐으므로 회사를 고를 재량이 없다.
  - 제외 목록 = D4 제외 목록(`eval/d4_excluded.json`) + D4 포함 10곳의 고유번호. 이것을 `eval/d5_excluded.json`으로 고정한다.
  - 20~30번의 기업개황·공시 목록은 D4 때(2026-10-15) 받아 둔 기록이다(`eval/d4_candidates/`). 쓸지, 다시 받을지는 8절에서 정한다. 첨부 이름은 화면에서 새로 기록한다(20번도).
- **합성 스캔:** D4 3.3과 같은 세 조건(`eval/d4_scan.py`)
- **받기:** D4 10절 "받는 사람 변경"과 같다. 사용자가 첨부 이름을 기록하고, Claude가 `eval/d4_download.py`로 받는다(사용자 승인).

## 5. 정답 밖 칸의 판정 기준 (D4 4.5에 더함)

- 정답 밖의 표시 없는 칸은 엑셀에서 다음 넷이 **모두** 인쇄와 같게 읽히면 `ok`다. 하나라도 틀리거나 알 수 없으면 `wrong`이다.
  - 재무제표(시트)
  - 계정명
  - 기간 열
  - 금액
- D4는 이 기준을 실행 뒤 Codex 결과 검토로 바로잡았다(D4 결과 보고서 6.1절). D5는 처음부터 이 기준으로 판정한다.
- 기준의 예(D4에서 판정한 것):
  - 세 열 재무상태표의 "전기초" 열에 든 인쇄값: ok
  - 손익 행이 재무상태표 시트에 든 것: wrong
  - 기간 머리글을 알 수 없는 열에 든 맞는 금액: wrong
  - 다른 표(자본변동표)의 행이 포괄손익계산서 시트에 든 것: wrong. 같은 포괄손익계산서에 같은 행·기간·값이 인쇄돼 있으면 ok

## 6. "제목 미확인 표"

- 제품은 제목을 읽지 못한 표를 "제목 미확인 표"로 따로 두고 모든 칸을 표시한다.
- 채점기는 이 표를 어느 정답 재무제표와도 짝짓지 않는다. 그래서 다음과 같이 된다.
  - 그 칸들: 정답 밖 칸(표시됨, 목록으로만 보고)
  - 그 표에 해당하는 정답 칸: 빠짐
- 빠짐이 가리켜졌는지는 D4 4.4를 따른다. 텍스트 PDF에서는 S2가 될 수 있다(제품에 불리한 쪽).
- 보고서에 "제목 미확인 표"의 수와 칸 수를 따로 적는다.

## 7. 실행 (D4 7절에 더함)

- D4에서 실제로 쓴 실행 스크립트를 절차서에 넣는다(`docs/D5_RUN_PROCEDURE.ko.md`). 스크립트는 절차서의 명령을 순서대로 담고, 전원 연결을 기다리며, 앱과 분리해(`nohup`) 실행한다.
- 실행 전에 전원 연결과 저장 공간을 확인한다.
- 판정 파일 폴더는 실행 폴더마다 따로 둔다.

## 8. 사용자 결정 사항

1. D5를 할지, 회사 수(제안: 10곳)
2. 20~30번 후보의 기업개황·공시 목록: D4 때 받은 기록을 쓸지(제안: 쓴다. 같은 기간의 공시 목록이고 받은 시각이 기록돼 있다), 다시 받을지. 31번부터는 새로 받는다(OpenDART 조회 승인).
3. 포함된 회사의 OpenDART 재무제표 조회 승인
4. 감사보고서 PDF 받기 승인(첨부 이름은 사용자가 기록)
5. 합성 스캔 3조건 그대로, 반복 실행 없음(제안: D4와 같음)

## 9. 한계 (D4 9절에 더함)

- D5의 제품 수정은 D4 문서의 결과를 보고 만든 것이다. 같은 종류의 결함(재무제표 경계, 계정명)에 맞춘 수정이 새 문서에서도 통하는지가 D5가 재는 것이다.
- 회사 순서는 D4와 같은 모집단의 다음 순번이다. 두 평가의 회사는 겹치지 않지만, 같은 순서 규칙에서 나온다.
