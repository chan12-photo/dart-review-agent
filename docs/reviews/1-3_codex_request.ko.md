## 요청문

이 저장소는 OpenDART 재무제표로 상장사의 기간별 수치를 비교하고, 비교 기준이 맞지 않으면 비교를 거절하는 도구다. Claude가 만든 **재무 도메인 규칙**과 **개발용 질문·정답**을 독립적으로 검토해 줘. 같은 사람이 정답과 규칙을 둘 다 만들었기 때문에, 같은 착각이 양쪽에 들어갔을 수 있다. 그 착각을 찾는 것이 목적이다.

**지킬 것**
- `AGENTS.md`를 먼저 읽고 따른다. 인증키 파일을 열지 말고, API를 호출하지 말고, 추적되는 파일을 수정하지 않는다.
- 근거는 로컬 `cache/`의 원본 응답으로 확인한다.
- 칭찬은 필요 없다. 틀렸거나 근거가 약한 것만 구체적으로 알려 줘.

**읽을 것**
- 범위와 배경: `docs/SCOPE.ko.md`, `docs/ROADMAP.ko.md`
- 데이터 조사: `docs/DATA_NOTES.ko.md`
- 규칙: `dart_review/periods.py`, `accounts.py`, `facts.py`, `compare.py`, `review.py`
- 정답 규칙과 질문: `docs/GOLD_RULES.ko.md`, `eval/dev_questions.json`, `eval/build_gold.py`, `eval/dev_gold.json`
- 테스트: `tests/`, `scripts/check_trap_tests.py`

**검토할 것**
1. **독립 재계산:** `dart_review`를 import하지 않는 너만의 코드로 `cache/` 원본에서 12개 질문의 정답(금액, 변화량, 변화율, 상태)을 다시 계산하고 `eval/dev_gold.json`과 비교해 줘. 다른 값이 있으면 어느 쪽이 맞는지 근거와 함께 알려 줘.
2. **데이터 조사 주장:** `DATA_NOTES.ko.md`의 주장 가운데 캐시로 확인할 수 있는 것을 표본으로 다시 확인해 줘. 특히 칸 의미 표(1절), 현금흐름 누적 근거(2절), 계정 오표기(3절), 재작성 표(4절).
3. **규칙의 논리:**
   - `periods.py`의 칸-기간 표가 1분기·반기·3분기·사업보고서와 IS/CIS/CF/BS 모두에서 맞는가
   - `compare.py`의 상태 판정 순서가 합리적인가
   - `review.py`의 재작성 판단(두 보고서 사이에 재작성이 접수됐으면 확인 필요)이 너무 느슨하거나 너무 엄격하지 않은가
   - `accounts.py`의 이름 대체 규칙이 엉뚱한 행을 고를 위험이 있는가
4. **판단이 갈리는 정답:** 아래 결정이 타당한지 의견을 줘. 동의하지 않으면 대안과 이유를 알려 줘.
   - 연결·별도 언급이 없으면 연결 (`GOLD_RULES` 2절)
   - dev05: 연결·별도는 나란히만 보여 주고 차이를 "변화"처럼 계산하지 않는다. 그런데 "연결이 별도보다 95.6조 많다"는 말까지 막아야 하는가?
   - dev07: 기준 값으로 재작성된 2024년 영업이익(+47.80%)을 쓰고, 원래 공시 값(+59.07%)은 메모로만 남긴다
   - dev08: 2023년 말 값의 재작성을 근거로 2024년 3분기말 값의 기준이 다를 수 있다고 보고 `확인 필요`로 답한다
   - dev12: "이익"은 되묻는다 (영업이익을 기본값으로 쓰지 않는다)
   - 변화율 반올림(소수 둘째 자리, 0.005 올림)과 부호 전환 시 변화율 생략
5. **빠진 함정:** 이 데이터와 범위(계정 6개, 2023~2025, 개발용 3곳)에서 규칙과 질문 세트가 놓친 비교 함정이 있는지.
6. **테스트의 약점:** 통과는 하지만 실제로는 아무것도 확인하지 않는 테스트가 있는지. (1-2에서 실제로 하나 있었다: 연결·별도 테스트가 다른 규칙 때문에 통과하고 있었다)

**답의 형식**
- 발견 사항마다: 심각도(치명 / 중요 / 사소), 위치(파일:줄 또는 질문 ID), 근거(원본 값, 실행한 명령과 결과), 제안
- "판단이 갈리는 정답"은 동의 / 비동의 / 조건부로 따로 정리
- 마지막에 직접 확인한 것과 확인하지 못한 것을 구분해서 적기
