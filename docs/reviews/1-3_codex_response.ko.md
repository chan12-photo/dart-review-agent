## 2. 재작성 확인의 새 설계 (R1, R6)

1. 비교 값과 기준 값이 **같은 보고서**에 있으면 같은 기준이다. 앞 보고서에서 기준 기간 값이 달랐으면 메모만 남긴다.
2. **두 보고서**가 필요하면 두 보고서와 그 사이 연도의 사업보고서에서 대상 계정의 모든 칸을 모은다. 손익 반기·3분기 보고서에서는 "누적 − 3개월"로 앞 분기의 누적을 구한다. 이 값은 앞 보고서가 직접 보여 주는 값이고, 기준 확인에만 쓴다.
3. 같은 기간·같은 통화의 값이 보고서마다 다르면 → `확인 필요`(관찰된 재작성).
4. 다르지 않더라도 두 보고서가 같은 값으로 **이어지지 않으면** → `확인 필요`. 필요한 사업보고서가 없거나, 013이거나, 계정을 쓸 수 없는 경우를 포함하고, 그 이유를 적는다.
5. 이어지고 모두 같으면 → `비교 가능`. 메모에는 "관찰한 범위에서 재작성 없음"이라고 적는다. 재작성이 없다는 증명은 아니다.

실제 데이터에서의 결과:
- dev02(삼성전자 3분기말 자산)는 2024년 말과 2023년 말 값으로 이어져 `비교 가능`이다.
- dev06(카카오 2023 3분기 대 2분기)은 "3분기 누적 − 3분기 3개월 = 반기 누적"으로 이어져 `비교 가능`이다. 수정 전에는 이 연결을 확인하지 않고 통과시키고 있었다(Codex E4).
- dev08은 관찰된 재작성 때문에 `확인 필요`다.
- 사업보고서를 없애거나 013·빈 응답으로 바꾸면 dev02와 dev08 모두 `확인 필요`가 된다.

## 5. 결과

- 테스트 68개 → **87개**, 모두 통과
- 변이 검사 7개 → **10개**, 모두 잡힘. Codex R1·R3·R4의 순진한 버전을 추가했다
- 정답 13개(dev13 추가)가 독립 계산과 규칙 코드 사이에서 모두 일치한다. 기존 12개의 숫자는 Codex 독립 재계산표와 같다
- 이 과정에서 Claude가 추가로 찾아 고친 것:
  - 테스트 클래스가 키 로더를 `fail`이라는 이름으로 정의해 unittest의 `fail`을 덮어쓰고 있었다. 단언이 실패하면 원인 대신 TypeError가 났다
  - 합성 테스트에서 반기·3분기 보고서의 접수번호가 같았다
  - 정답 대조가 금액을 부분 문자열로 찾아 `1`이 `2,230,…` 안에서 맞는 것으로 처리됐다. 이제 숫자를 통째로 비교한다
  - 변이 검사가 `subTest` 실패를 테스트 이름으로 인식하지 못했다
