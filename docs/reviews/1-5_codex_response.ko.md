# Codex 검토 반영 내역: 평가 실행기와 채점 규칙 (1-5 실행 전)

- 작성: 2026-10-07, Claude
- 검토 원문: [1-5_codex_result.ko.md](1-5_codex_result.ko.md) (기준 커밋 `8c19b82`), 중단 기록: [1-5_codex_partial.ko.md](1-5_codex_partial.ko.md)
- 방식: 주요 지적(E1~E6)은 **Claude가 직접 재현한 뒤** 반영했다. 고친 뒤에는 수정을 메모리에서 되돌려 새 테스트가 실패하는지 확인했다(E2, E3, E4).
- 원칙: Codex의 권고대로 13문항의 정답은 바꾸지 않았다. 바꾼 것은 평가 장치(채점기, 실행기, 기록)와 계약 문서이고, 본문 검토 기준은 모델 실행 전에 고정했다.
- 결과 요약: E1~E10 모두 반영(E9는 실행 후로 미뤄도 된다고 했지만 작아서 함께 고침). 테스트 139개 → 166개.

## 1. 발견 사항

| 항목 | 판단 | 재현 | 바꾼 것 |
|---|---|---|---|
| E1 잘못된 타입이 평가 전체를 중단, 완료 기록 소실 | **수용** | 답의 `account=[]`, 도구 인자의 `account=[]`·`month=12.0`이 모두 TypeError | 답·도구 인자를 타입부터 검사(형식 오류·도구 오류로 처리). 문항 단위로 격리하고, 평가기 자체 버그는 `evaluator_error`로 따로 기록·집계, 하나라도 있으면 실행기가 실패 코드로 끝남. 실행 정보는 시작 시, 문항 결과는 끝나는 즉시 저장. 도구 이름은 오류 문구에 되돌려 쓰지 않음 |
| E2 도구 오류가 지어낸 숫자의 근거가 됨 | **수용** | 없는 도구 이름 `unknown_영업이익률99.9%`의 오류 문구로 "99.9%"가 통과 | `error` 키가 있는 결과는 숫자 근거가 되지 않음. 질문에서는 연도만 근거. 계약 문서(EVAL_DESIGN 4절)도 "모델이 본 모든 숫자"에서 "성공한 도구 결과"로 고침 |

| E4 허용 오차가 반올림·버림보다 넓음 | **수용** | 근거 1.24조에 "1.3조", 3.275조에 "약 4조"가 통과 | "표시 자리에서 반올림하거나 버린 값과 정확히 같다"로 바꿈. Codex가 든 정상 사례(1.19조→1.1조, 3.275조→3.3조)는 통과 유지 |

## 2. 그 밖의 의견 (Codex 3·5·7절)

| 의견 | 반영 |
|---|---|
| 프롬프트의 예시 금액 "333.6조 원"이 dev01·dev05의 실제 값과 겹침 | "N.N조 원", "N,NNN억 원"으로 바꾸고 프롬프트 버전을 `answer-v2`로 올림 |
| ①은 자연어 규칙 기준선이 아님 | EVAL_DESIGN 1절에 명시. 기준선은 로드맵 2-2 |
| ②와 ③의 차이를 순수한 해석 손실로 보지 말 것 | EVAL_DESIGN 1절에 명시 |
| dev12에 후보를 주므로 후보를 스스로 찾는 능력은 재지 않음 | EVAL_DESIGN 1절에 명시 |
| `think=None`은 "기본값 사용"이고, `truncate=false`의 실제 효과는 확인이 필요 | EVAL_DESIGN 7절에 명시. 실제로 돌아온 thinking·종료 이유·토큰을 원시 응답으로 기록 |
| dirty 표시만으로는 수정된 소스를 복원할 수 없음 | 커밋하지 않은 변경이 있으면 모델 실행을 시작하지 않음(`--allow-dirty`로만 우회, 기록됨). 실행마다 정답·질문·프롬프트·도구·스키마의 해시를 기록 |
| 80% = 11/13, 자동 점수와 사람 검토의 적용 순서를 실행 전에 고정 | EVAL_DESIGN 5절과 `finalize.py`. 사람이 바꿀 수 있는 것은 "판정 불가 표기"의 인정뿐 |
| 이상한 도구 호출 4개 테스트는 예산 때문에 네 번째가 실행 경로에 닿지 않음 | 응답당 3개씩 두 묶음으로 바꿔 모든 모양이 실행되게 함 |
| ModelError 테스트가 시도 1회·응답 0회와 완료 결과 보존을 보지 않음 | 시도·응답 집계, 요청 기록의 오류, 중단 시 완료 문항 보존을 각각 테스트 |
| R3 변이가 단언 실패가 아니라 테스트 오류로 잡힘 | 반영하지 않음(Codex도 중단 사유가 아니라고 함). 다음에 그 테스트를 고칠 때 정리 |

## 3. 반영하지 않았거나 남은 것

- **한국어 날짜·숫자 표기의 전면 지원:** 하지 않음. 지원 범위를 문서에 적고, 읽지 못한 표기는 판정 불가로 세며 사람이 확인하는 절차를 둠(Codex 권고와 같음).
- **본문 의미의 자동 판정:** 하지 않음. 사람 검토로 대신하고 기준을 실행 전에 고정함. 새 LLM 심판은 넣지 않음.
- **실제 Ollama 호환성:** 아직 확인하지 않음. 1-5 첫 단계에서 요청 1회로 확인하고, 문제가 있으면 결과를 보기 전에 고친다.

## 4. 검증

- 테스트 166개 통과. 새로 클론한 폴더에서 캐시와 키 없이 통과.
- ① 규칙만 13/13, 정답 13개 대조 일치, 규칙 변이 10/10 검출.
- 수정 되돌리기 확인: 허용 오차를 예전 방식으로, 오류 결과를 근거로, 부호 표현을 부분 문자열 검사로 되돌리면 각각 새 테스트가 실패한다.
