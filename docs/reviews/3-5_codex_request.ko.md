- 이 검토를 반영한 뒤 사용자 승인을 받아 사전 등록(⑤)을 커밋하고 실행한다. 사전 등록 뒤에는 생성 규칙, 정답, 기준을 바꿀 수 없다.

## 요청문

`AGENTS.md`를 따른다. 인증키, OpenDART API, Ollama는 쓰지 않는다. 다음은 허용한다.
- 로컬 캐시(`cache/`)에서 봉인 4곳의 응답을 읽는 것. 정답 검증에 필요하다.
- 제품의 도구 함수와 규칙 해석(`dart_review.tools`, `dart_review.baseline.read`)을 개별 질문에 호출해 보는 것.

다음은 **하지 않는다**:
- `eval/run_eval.py`로 템플릿 질문 전체를 실행하는 것. 규칙만(`baseline`) 방식도 포함한다. 사전 등록 전에 결과를 보지 않기 위해서다.
- 추적 파일을 수정하는 것. 결과는 `docs/reviews/3-5_codex_result.ko.md`에만 쓴다.

칭찬은 필요 없다. 틀렸거나, 근거가 약하거나, 결과를 실제보다 좋게 보이게 할 수 있는 것만 적어 줘. 발견마다 다음을 적어 줘.
- 심각도(치명/중요/사소)
- 위치(파일:줄)
- 근거(명령과 결과)
- 제안

그리고 "사전 등록 전에 고칠 것"과 "기록만 할 것"을 나눠 줘.

계약은 `docs/EVAL_CONTRACT_3-5.ko.md`다. 대상은 `708759a`(계약 초안)부터 HEAD까지의 변경이다. 3-1 계약과 그 검토(`docs/EVAL_CONTRACT_3-1.ko.md`, `docs/reviews/3-1_*`)가 배경이다.

### Part A. 정답 (가장 중요)

1. `python3 eval/build_template_gold.py --check`와 `python3 eval/build_template_questions.py --check`를 돌려 줘.
2. **정답 쪽 규칙이 맞는가** (`eval/build_template_gold.py`):
   - 칸-기간 대응(`own_column`, `prior_year_column`)이 DATA_NOTES 1절과 맞는가. 특히 다음을 봐 줘.
     - 손익 분기의 3개월·누적 칸
     - 현금흐름 분기의 누적 칸
     - 재무상태표 분기 보고서의 전기 칸(전년 말)
   - A6의 연결 규칙(`link_pairs`): 두 쌍만으로 충분한가. 제품의 `review_change`가 보는 다른 값이 있어서 둘의 판정이 갈릴 수 있는가.
   - 조회의 1년 뒤 보고서 규칙: `not_cached`와 `no_column`의 구분이 맞는가.
   - 행 고르기(`select_cell`): IS·CIS 순서, 비표준 행 이름표, 제외 조건.
3. **원본을 직접 읽어 대조해 줘.** 유형마다 몇 문항 이상, 특히 다음을 봐 줘.
   - 재작성 7문항(태그 "재작성")
   - 부호 전환 몇 문항
   - 비표준 행 4문항
   - 금액, 기간, 접수번호, 상태를 독립적으로 확인해 줘.
4. **불일치 판정 8건** (`eval/template_3-5/gold_disagreements.json`): 근거가 충분한가. 비표준 행을 "값 있음"으로 둔 것이 정당한가(계약 5.3절은 이것이 데이터를 본 뒤의 결정이라고 밝힌다).
5. **제외 0개가 맞는가.** 정답 규칙이 너무 관대해서 정답을 확정할 수 없는 조합까지 받아들이고 있지는 않은가.

### Part B. 질문

1. 질문 문장이 정답의 해석과 맞는가. `tests/test_template_eval.py`의 문장 검사가 놓치는 것이 있는가. 예를 들면 다음과 같다.
   - "전년 동기 대비"
   - "1년 전보다"(재무상태표)
   - "작년 3분기"
   - "재작년"
   - 별칭과 조사
   - 4분기 문장
2. 기준 날짜 2026-10-08에서 상대 연도의 해석이 GOLD_RULES 2절과 3-1 계약과 맞는가.
3. 유형 배분과 표현 틀이 결과를 유리하게 만들 여지가 있는가. 예를 들어 어려운 칸이 적게 뽑히도록 짜여 있지는 않은가. 시드 추출이 실제로 회사별로 고르게 이루어지는가.
4. 함정(B) 유형의 기대 결과가 3-1 계약 4.2절과 맞는가. B5의 무관한 회사, B8의 복합 질문도 봐 줘.

### Part C. 평가 도구

1. **채점기 수정**(`eval/scoring.py`의 해석 연도): 계약 6.1절과 같은가. 근거 없는 숫자를 놓치게 만드는 경로가 생겼는가. 예를 들어 되묻기 상태의 답 전체에서 연도를 허용하는 것이 지나친가.
2. **표본 검토**(`eval/finalize.py`의 `review_sample`, `required_reviews`):
   - 계약 8절과 같은가.
   - 검토자가 표본을 바꾸거나 확대 규칙을 피할 수 있는가.
3. **판정기**(`eval/judge.py`의 3-5 부분):
   - 기준, 분모, 판정 보류 조건이 계약 9절과 같은가.
   - 잘못된 수치 답의 두 방향 분류(`wrong_direction`)가 위험한 답을 "조심한 방향"으로 잘못 넣을 수 있는가.
   - 3-1의 판정 동작이 바뀌지 않았는가.
4. **실행기**(`eval/run_eval.py`): 질문 파일마다 고정 기록을 고르는 방식이 우회될 수 있는가. 예를 들어 질문 파일의 `freeze` 값을 바꾸면 어떻게 되는가.
5. `.gitignore`를 `/runs/`로 바꿨을 때 원치 않는 파일이 추적될 수 있는가.
