# 3-5 사전 등록 전 Codex 검토 결과

검토 대상은 `708759a..89c8d3b`이다. 제품 코드, 기존 평가 기록, 질문·정답 및 캐시는 수정하지 않았다. `eval/run_eval.py`의 템플릿 전체 실행과 Ollama·OpenDART API 호출은 하지 않았다. 아래 합성 호출은 평가기 함수만 메모리에서 시험한 것으로, 제품 평가 결과가 아니다.

## 사전 등록 전에 고칠 것

### 1. 중요 — 고정 날짜·회사 집합·고정 기록을 엄격 판정기가 확인하지 않는다

- **위치:** `eval/run_eval.py:251-256,381-384,388-410`, `eval/judge.py:137-153,199-209,244-268`, `docs/EVAL_CONTRACT_3-5.ko.md:37-45,237-255`.
- **근거:** 질문 파일은 기준 날짜를 `2026-10-08`, 고정 기록을 `eval/freeze_3-5.json`으로 지정한다. 그러나 CLI의 `--reference-date` 기본값은 `date.today()`다. 2026-10-09에 `run_eval.build_parser().parse_args(['--mode','baseline'])`를 호출하면 `2026-10-09`가 나왔다. `judge.check_runs`는 두 실행의 날짜가 **서로 같은지만** 확인하고 계약의 `2026-10-08`과 대조하지 않는다. 회사 집합도 실행 사이의 일치만 검사한다. `freeze_file()`은 질문 JSON의 `freeze` 경로를 그대로 따르고, `frozen_differences()`는 그 파일의 `evaluator_paths`를 신뢰한다. 지금은 사전 등록 전이므로 `eval/freeze_3-5.json`이 없는 것은 예정된 상태이나, ⑤ 이후에도 경로·필수 파일 목록의 독립 확인이 없다.
- **영향:** 잘못된 날짜나 다른 회사 집합으로 두 방식을 동일하게 실행해도 계약 위반이라는 이유로 반드시 `판정 보류`가 되지는 않는다. 질문 파일이나 고정 기록에 실수로 다른 경로·검사 대상을 적으면 고정 게이트가 약해진다. 질문 해시의 실행 간 일치 검사만으로는 사전 등록한 R2와의 일치를 증명하지 못한다.
- **제안:** 3-5 엄격 판정에서는 질문 파일의 기준 날짜, 회사 집합 `sealed-3-1`, 고정 기록의 정확한 경로와 필수 평가 파일 목록을 계약 상수 및 R2 기록과 대조한다. CLI는 3-5 실행에서 명시적 기준 날짜를 요구하거나 질문 파일의 날짜를 사용하고, 값이 다르면 시작 전에 거부한다. 3-1의 기존 규칙은 별도 분기로 유지한다.

### 2. 중요 — 되묻기 상태의 본문 전체가 ‘제안 연도’ 예외를 받는다

- **위치:** `eval/scoring.py:178-186`, `tests/test_scoring.py:65-70`, `docs/EVAL_CONTRACT_3-5.ko.md:175-183`.
- **근거:** 코드의 `answer.status == '되묻기'` 조건은 `answer.answer`의 **모든 줄**에 `proposed_years`를 허용한다. 메모리 시험에서 B6-001 정답과 `proposed_years=[2039]`를 사용하고 본문에 `2039년 기준으로 비교하면 다릅니다. 어떤 이익인지 알려 주세요.`를, 실제 확인 질문에는 `영업이익과 당기순이익 중 어느 것을 말씀하셨나요?`를 넣었다. 제안 연도 없이 `ungrounded=['2039년']`, 자동 통과 `False`; 제안 연도를 넣으면 `ungrounded=[]`, 자동 통과 `True`였다. 2039년은 질문·도구 결과에 없는 연도이며, 본문의 첫 문장은 해석 제시로 제한되지 않는다.

- **제안:** `clarifying_question`과 본문에 정확히 복제된 확인 질문, 그리고 `이렇게 이해했습니다`로 시작하는 줄에서만 제안 연도를 허용한다. 나머지 본문은 질문·성공한 도구 결과를 근거로 검사한다. 현재 실제 되묻기 렌더러가 확인 질문을 본문에도 복제하므로 그 구간을 정확히 인식하는 회귀 테스트가 필요하다.

### 3. 중요 — 사람이 확인한 수치·기간 설명 오류를 ‘조심한 방향’으로 분류할 수 있다

### 5. 중요 — ‘95% 상한 약 0.6%’의 통계적 전제가 명시되지 않았다

- **위치:** `docs/EVAL_CONTRACT_3-5.ko.md:7-15,248-251,278-284`, `eval/judge.py:317-323`.
- **근거:** 판정기는 수치 답이 0건 틀렸으면 `1 - 0.05 ** (1/n)`을 계산한다. 이 식을 오답 확률의 95% 상한으로 해석하려면 답들을 독립·동일 분포의 시행으로 볼 근거가 필요하다. 여기서는 같은 회사·계정·보고서 칸이 여러 질문에서 반복되고, 답한 문항 수도 제품의 선택에 달린다. 계약 9절은 상관을 언급하지만 11절의 한계에는 직접 쓰지 않았고, 서두는 ‘약 0.6%’를 상한으로 단정한다.
- **영향:** 결과가 0건이어도 이 숫자를 전체 질문 분포의 엄격한 신뢰 상한으로 읽으면 실제 위험을 과소평가한다.
- **제안:** 사전 등록 문구와 보고서 형식을 ‘독립 시행을 가정한 참고 계산’으로 한정한다. 답한 수 `n`, 회사×기준×계정별 묶음 수, 같은 칸을 반복 사용한 정도를 함께 표시한다. 사람의 자유로운 질문으로 일반화하지 않는다는 기존 제한도 유지한다.

## 결론

원본 금액과 A6 연결 상태에서는 확인한 범위의 불일치를 찾지 못했다. 그러나 **고정 계약 검사, 제안 연도 예외, 위험 방향 분류, 일부 함정 유형의 추출 균형, 통계 문구**는 사전 등록 전에 정리해야 한다. 불일치 8건의 사용자 승인도 아직 기록되지 않았다. 수정·승인 뒤 생성기 `--check`와 직접 관련 테스트를 다시 수행하고, 그다음에만 R2로 고정하는 것이 적절하다. 이번 검토에서 템플릿 전체 평가나 모델 실행은 하지 않았다.
