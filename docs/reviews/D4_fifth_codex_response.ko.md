# D4 5차 검토(Codex)에 대한 응답 (2026-10-14)

- 대상: `docs/reviews/D4_fifth_codex_result.ko.md` (기준 `fcdd13f`). 결과 파일은 그대로 커밋했다(`5175eba`).
- **결론: 9건을 모두 받아들였다. 다만 고친 방식은 두 가지로 나뉜다.**
  - **실제 결함(1·5·6번)은 코드를 고쳤다(`273383e`).** 정직하게 실행해도 틀린 정답이나 틀린 후보 판정이 나오는 경로다.
  - **2·3·7번은 장치를 더하지 않고 계약에 신뢰 경계로 적었다(계약 1.3).** 셋 다 실행하는 사람이 일부러 등록되지 않은 입력을 넣는 경우다. 이 프로젝트는 한 사람이 실행하므로 코드로 끝까지 막을 수 없다. 계약이 코드보다 강하게 말하던 문장도 고쳤다.
  - 4·8·9번은 한계로 기록했다.
- **이렇게 정한 이유(사용자 결정, 2026-10-14):** 4차부터 지적의 대부분이 제품이 아니라 Claude가 덧붙인 평가 장치의 빈틈이었다. 장치를 더할수록 검토할 표면도 커져서, 이대로는 D4를 돌리지 못한다. 그래서 6차 검토는 "신뢰 경계 안에서 ④를 막는 결함이 있는가"만 묻는다.
- 고치기 전에 1·5·6번 반례를 다시 돌려 Codex와 같은 결과를 확인했다. 새 시험 4개는 고치기 전 코드에서 실패하고 고친 코드에서 통과한다.

## 1. 고친 것

| # | 심각도 | 처리 |
|---|---|---|
| 1 쉼표 없는 금액을 정답에 더할 수 없음, 모두 `ignore`하면 0칸 공식 | 치명 | 사람이 적는 칸이 쉼표 없는 인쇄값("1000")을 받는다. 부호·단위·자리 검사는 같다. `no_grouped_amounts`를 `ignore`하면 그 문서는 `unscorable`이 된다(숫자가 있는 표가 정답 없이 남기 때문이다). 시험: "1000 2000"을 적어 채점까지(정답 2칸, 맞음 1, 빠짐 1), `ignore`하면 `scorable=false` |
| 5 사람이 더한 재무제표의 쪽 범위 | 중요 | 정답에 PDF 쪽 수를 기록한다(개발 PDF 5개: 147, 139, 146, 126, 42쪽). `add_statement`는 그 범위 안이어야 하고, id는 "제목@첫 쪽", 제목은 그 종류여야 한다. 다른 재무제표와 쪽이 겹치면 `overlap_note`가 있어야 한다(같은 쪽 위아래에 두 표가 있을 수 있으므로 겹침 자체를 오류로 보지 않는다). PDF가 없으면 쪽 수를 모르므로 더할 수 없다 |
| 6 후보 선택의 기록 누락과 기간 | 중요 | 공시 목록을 기록하지 않은 후보는 "기록 부족"이다(빈 목록과 구별한다). 접수일이 2026-01-01~06-30 밖인 공시는 쓰지 않고 `out_of_period`에 적는다. 제외 회사는 후보 기록이 아니라 따로 주는 고정 목록(`--excluded`)으로 정한다 |

- 개발 정답 5개를 새 정답 생성기로 다시 만들었다. 칸·재무제표·매핑 항목은 같고 쪽 수만 새로 붙어서, after-fourth 기록과 점수를 그대로 쓴다. 제품은 바꾸지 않았으므로 다시 재지 않았다.

## 2. 신뢰 경계로 적은 것 (계약 1.3)

| # | 처리 |
|---|---|
| 2 등록 점검이 외부 등록 JSON과 아무 원격을 믿음 | 계약에 적었다. `--register`는 R에 커밋된 `eval/register_d4.json`, `--remote`는 GitHub의 `origin`이어야 하고, 이것은 실행하는 사람이 지킨다. 도구는 주어진 기록과 원격을 비교할 뿐이다 |
| 3 점검 통과가 실제 채점 입력과 이어지지 않음, 적힌 해시만 비교 | 계약에 적었다. `source_verified`는 `--pdf`로 실행할 때만 파일 해시를 직접 계산한다. 저장된 보고서를 다시 채점할 때는 적힌 해시를 비교한다. 공식 실행은 ⑦에서 고정한 명령만 쓰고, 채점기는 그것을 스스로 확인하지 않는다 |
| 7 모델 digest를 `ollama list`로 읽음 | 계약에 적었다. 공식 실행은 Ollama를 7절의 명령 하나로 기본 주소에 띄우므로, CLI가 보는 서버와 제품이 부르는 서버가 같다고 본다. 도구는 따로 확인하지 않는다 |

- 이 셋을 코드로 더 막지 않은 것은 판단이다. 공식 실행기, 원격 주소 고정, 제품 URL 조회는 모두 만들 수 있다. 하지만 그래도 실행하는 사람이 그 실행기를 쓰지 않으면 같은 문제가 남는다. 그래서 확인은 공개 기록(커밋, 태그 push 시각)과 독립 검토에 맡겼다.
