# D4 계약 2판·수정 코드 재검토 결과

- 검토일: 2026-10-10. 범위: `78f7b76..dad0c32`, 지정된 개발 PDF 여섯 개, 합성 입력, 저장된 개발 측정. 시작할 때 작업 트리는 깨끗했다.
- **판단: 현 상태로 ④ 모집단 고정과 D4 사전 등록을 진행하지 말 것.** 아래 채점·정답 생성의 반례를 먼저 막아야 `S1=L1=S2=0`이 의미가 있다. 반례는 함수 수준의 합성 사례이며 신규 회사 10곳의 실제 발생률을 말하지 않는다.
- 인증키 파일, OpenDART API, Ollama, 3-1 봉인 질문은 사용하지 않았다. 지정된 여섯 PDF 외의 그 폴더 파일은 읽지 않았고, 추적 파일은 이 결과 문서 외에 수정하지 않았다.

## 1차 지적 네 가지의 재현 결과

1차 결과의 마지막 절에 있는 명령을 현 코드에 맞춰 다시 시험했다. 둘째 명령은 현 `classify`의 `extraction.problems`, `statement.columns/unit`과 좌표 있는 `Cell` 계약에, 셋째는 `claimed: dict`, `recent_from`, `reread`에 맞게 합성 객체만 바꿨다. 넷째의 `_collapsed`는 삭제되어 `_sums_by_coincidence`와 `_check_sum`으로 같은 수치 배열을 시험했다. 옛 명령을 글자 그대로 실행하면 둘째·셋째·넷째는 현재 함수 계약과 맞지 않아 결과 비교가 되지 않는다.

| 옛 반례 | 이번 명령·관찰 | 판정 |
|---|---|---|
| `기본주당이익 | 47`가 열에서 어긋남 | 1차 결과의 첫 `read_statement` 합성 명령: 행 자체는 여전히 빠지지만 `problems=["표에 넣지 못한 금액 1개 (1쪽 '47' (기본주당이익))…"]` | **조용한 누락은 막음.** 행 복원까지 된 것은 아님 |
| 다른 계정의 같은 값·부호 반전·중복값의 빠진 항목·다른 기간 숫자 | 수정한 `classify` 합성 호출: `dart_value=1`은 `label_review=1`도 남음; BS 부호 반전은 `sign_review=1`; 같은 1,000을 가진 다른 계정은 `missing=[…status:'silent']`; 위치가 없는 `pdf_only` 반례는 `unconfirmed=1` | 기존 자동 정답·누락 은폐 경로는 대체로 막음. `dart_value`를 값 맞음으로 세는 수치와 계정명 검토는 함께 읽어야 함 |
| 사진의 같은 이름·값인 서로 다른 두 줄 | 현재 `_add_row_by_tokens`에 별도 높이의 OCR 토큰 두 개를 차례로 넣음: 첫 행 `검사 통과`, 계정명 증거는 `OCR (숫자만, 계정명 미확인)`; 둘째 뒤 `rows=2, checks=2`, 둘째 토큰 청구됨 | 토큰이 있는 두 행의 병합은 막음. 계정명 미확인은 여전히 칸의 `확인 필요`가 아님 |
| `[10,5,5]`를 숫자만으로 접음 | `verify._sums_by_coincidence(10,[10,5,5])`는 `True`; 같은 높이의 세 세부 행으로 `_check_sum` 호출 시 `checked=0`, 소계 검산 불가 문제가 남고 네 칸 모두 `검사 통과` | 숫자 우연을 검산 **성공**으로 세지 않는 수정은 확인. 실제 오류의 칸 표시는 별도 문제(아래 6번) |

`server.py`의 이전 두 결함도 현 `transition`의 조건부 상태 전이와 `delete`의 삭제 실패 보존, `_error_message`의 패턴 제한으로 막혔다. 관련 임시 DB 시험은 아래에 적는다.

## 평가 전에 고칠 것

### 1. [치명] 빠진 칸의 같은 숫자 하나로 다른 행까지 표시됐다고 채점한다

- **위치:** `eval/d4_score.py:37-38, 62-90`; `docs/EVAL_CONTRACT_D4.ko.md:89-93`.
- **근거:** `./.venv/bin/python - <<'PY'`에서 정답을 `유동자산 당기 1,000`, `비유동자산 당기 1,000` 두 칸으로, 제품 행은 비우고 문제를 `"유동자산 당기 원본 금액 '1,000'을 읽지 않았다"` 하나로 만들어 `score(gold, report)`를 호출했다. 결과는 `missing=2, S2=0`이었다. 실제로 가리킨 것은 한 행뿐이다. 반대로 정답 한 칸과 `"유동자산 당기 칸을 읽지 못했다"`라는 문제는 계약 4.4가 허용한 행·기간 표시인데 `S2=1`로 채점됐다. 구현은 문서·행·기간·쪽을 보지 않고 따옴표 안 숫자의 집합만 본다. 이 중복 금액 판정은 계약 문구도 느슨하다.
- **제안:** 표시 증거를 칸 식별자(문서/재무제표/인쇄 행/기간/가능하면 쪽)에 연결한다. 금액만 적힌 문제는 그 재무제표에서 해당 금액이 **유일한 칸**일 때만 자동 인정하고, 중복이면 사람 판정으로 보낸다. 행·기간을 특정한 문제도 파싱하거나 검토 결과로 입력한다. 중복 금액·행 기간 문구 회귀 테스트를 넣고 계약 4.4를 함께 고친다.

### 2. [치명] 정답에 없는 미표시 오답은 공식 문턱을 통과할 수 있다

- **위치:** `eval/d4_score.py:92-110`; `docs/EVAL_CONTRACT_D4.ko.md:77-85, 95-115`.
- **근거:** 정답 `유동자산=1,000`과 제품 `유동자산=1,000; 주석 표 숫자=77(검사 통과)`를 `score`에 넣자 `not_in_gold=1, S1=L1=S2=0`이었다. 채점기는 여분 칸을 목록에만 두고 세 문턱에 반영하지 않는다. 계약은 사람 검토로 틀림 여부를 정한다고 하지만 **검토 판정을 공식 합격/불합격으로 합치는 규칙·입력 파일·검증 단계가 없다.** 개발 기록에도 정답에 없는 두 칸이 있었다(`REPORT.ko.md:54-60`). 그때는 두 칸 모두 표시됐으나, 미표시였을 경우 현재 수치 문턱은 통과한다.
- **제안:** `not_in_gold`의 각 칸에 사람 판정과 근거를 필수 입력으로 받아, 미표시로 잘못 추가된 칸을 별도의 공식 불합격 지표에 넣거나 S1/L1에 포함하는 명시적 계약을 정한다. 미판정 여분 칸이 있으면 합격 결론을 내지 못하게 한다. 정답의 `-` 기간 칸에 새 숫자가 생긴 경우도 시험한다.

### 3. [중요] 정답 생성기가 인쇄 행을 매핑 대상으로도 남기지 않고 누락할 수 있다

- **위치:** `eval/d4_gold.py:100-108, 125-146, 154-197, 215-232`; `docs/EVAL_CONTRACT_D4.ko.md:67-75`.
- **근거:** 작은 금액이 있는 합성 인쇄 줄을 페이지 높이의 93%에 두고 `cells_of`를 호출하자 `매출액 1,000/2,000`만 정답에 남고 `기본주당이익 47/48`은 `needs_mapping=[]`인 채 빠졌다. `_furniture_or_header`는 쉼표가 들어간 금액이 없고 하단 8%에 있으면 줄 전체를 버린다. 더 나쁜 경우를 `build`에 넣었다: 앞쪽 `A계정 47/48`, 하단 `B계정 47/48`, OpenDART에도 두 항목을 넣으면 결과 정답은 `A계정`만 포함하고 `needs_mapping=[]`이었다. `dart_only`가 `(기간, 절댓값)`의 **집합**을 써 중복 금액의 다른 행을 찾아내지 못했다. 모두 합성 위치·값이며 실제 개발 PDF에서 이 줄을 보았다는 뜻은 아니다.
- **근거(운영 차단):** 개발용 포스코 PDF에 `./.venv/bin/python eval/d4_gold.py …` → `270 cells, 27 to map`, 곧바로 `eval/d4_score.py … --reader rules` → `S1=L1=S2=0`이었다. 채점기는 미해결 `needs_mapping`을 거부하지 않는다. 현재 개발 기록은 사람이 검토했다고 서술하지만, 평가 도구는 확정 파일이나 검토 완료를 요구하지 않는다.
- **제안:** 페이지 하단/짧은 숫자 줄을 일괄 폐기하지 말고 금액 행 후보로 매핑표에 올린다. OpenDART 비교는 행 식별자와 중복 발생 수를 보존한다. 정답 생성 결과와 사람 확정 매핑을 분리하고, 모든 `needs_mapping` 및 행 수·기간 수 점검을 끝내기 전 채점 명령은 실패하게 한다.

### 4. [중요] 같은 제목의 표가 다시 나오면 두 번 채점한다

- **위치:** `eval/d4_gold.py:204-215`; `eval/d4_score.py:41-52, 66-110`.
- **근거:** 정답에 1쪽·5쪽 `연결재무상태표`를 각각 한 칸씩, 제품에도 해당 쪽의 맞는 한 칸씩 넣어 `score`를 호출했다. 실제 두 칸 모두 맞는데 결과는 `gold_cells=4, correct=2, missing=2, S2=2`였다. `gold_cells`를 제목만으로 고르고, `build`의 OpenDART 대조도 같은 제목과 `page >= 시작쪽`으로 뒤쪽 표를 앞쪽 표의 일부로 포함할 수 있다. 이번 개발 PDF 다섯 개에는 제목 중복이 없음을 정답 JSON으로 확인했다.
- **제안:** 표마다 시작/끝 쪽 또는 고유 ID를 붙이고 정답 칸·제품 표를 그 ID에만 연결한다. 같은 제목·다른 쪽 합성 테스트를 추가한다. 중복 표를 자동으로 구별할 수 없으면 사람 매핑 없이는 채점하지 않는다.

### 5. [중요] 금액 한 열의 오른쪽 주석 번호가 기간 값으로 통과한다

- **위치:** `dart_review/documents/statement.py:229-260, 288-299, 346-360`; `dart_review/documents/table.py:152-164`.
- **근거:** `Line/Word` 합성 표를 `당기` 한 금액 열(오른쪽 끝 350)과 그 **오른쪽** `주석` 열(끝 420)로 만들고 세 행 `매출액 1,000 | 1`, `영업이익 3,000 | 2`, `당기순이익 5,000 | 3`을 넣어 `read_statement`와 `check`를 호출했다. 결과의 열 머리글은 `['당기','당기 주석']`, 각 행은 `{0: 실제 금액, 1: 주석 번호}`였고 `problems=[]`, 여섯 칸 전부 `검사 통과`였다. 옛 `47` 누락은 문제로 보고되지만, 반대쪽 주석 배치에는 새 오인식이 남았다. 한 열의 합성 레이아웃이고 신규 평가 문서에서의 빈도는 확인하지 않았다.
- **제안:** 기간 머리글로 확인되지 않은 숫자 열을 기간으로 만들지 않는다. 오른쪽 주석 열은 머리글·위치로 구별하고 애매하면 해당 칸을 표시한다. 한 금액 열+오른쪽 주석, 두 금액 열+주석을 각각 회귀 시험한다.

### 6. [중요] 들여쓰기 추정으로 틀린 소계를 정상 검산하고, 검산 횟수도 과대 기록할 수 있다

- **위치:** `dart_review/documents/verify.py:91-102, 183-217, 239-251, 264-286`; `docs/EVAL_CONTRACT_D4.ko.md:105-106`.
- **근거:** `_check_sum`에 `소계=10`, 세 세부 행 `항목A=10(x0=10)`, `항목B=5(x0=20)`, `항목C=5(x0=20)`을 넣었다. **동등한 세 행**이라는 인쇄 구조를 가정하면 10≠20이지만, 현재 `_rank`는 10pt 들여쓰기를 하위 계층으로 보고 `checked=2`, 네 칸 모두 `검사 통과`, 문제 없음으로 냈다. 앞의 두 행이 실제 부모·자식이었다면 이 계산은 맞으므로 인쇄 구조가 불확실할 때 자동 검산 성공으로 확정하면 안 된다. 같은 높이로 넣으면 `_sums_by_coincidence`가 `checked=0`과 문서 수준 문제만 남기고 칸들은 여전히 `검사 통과`다. 별도 `_balance` 합성 재무상태표에서 당기 세 행만 있어 항등식은 한 열만 계산했는데, `check_sums`의 `sums_checked=2`였다(기간 열 수를 곱함).
- **제안:** 들여쓰기만으로 층을 확정할 수 없는 표는 검산 불가로 남기고 관련 칸을 사람 검토 대상으로 표시하는 기준을 정한다. `_balance`는 **실제로 값 세 개가 모두 있었던 기간**만 세도록 고친다. A4 분모·계산 가능한 합계 목록도 고정해 명칭의 ‘비율’과 맞춘다.

### 7. [중요] 제품 고정과 후보 PDF 제외 기준이 사전 등록 시점에 비어 있다

- **위치:** `docs/EVAL_CONTRACT_D4.ko.md:11-26, 42-50, 67-75, 117-121`.
- **근거:** 계약은 후보를 받고 정답까지 만든 **뒤** ⑦에서 제품 커밋 P를 고정한다. ⑤에서 제품을 돌리지 않는다는 문구는 있으나 문서 내용을 보고 제품 규칙을 고치는 것을 금지하거나 사후에 판별할 커밋 게이트는 없다. 또한 제외 3의 `PDF로 받을 수 있는 연결감사보고서가 없음`은 조회 경로, 재시도 범위, 정정 공시/여러 PDF 중 선택 순서, 파일이 열리지 않는 경우의 판정을 고정하지 않는다. 현재 후보 선정 기록이 없다는 것은 예정된 ④ 작업이므로 그 자체를 결함으로 세지 않았다.
- **제안:** P와 채점기 버전을 후보 문서 열람 **전** 고정하거나, 그 시점부터 ⑧까지 `dart_review/` 변경 금지·diff 검사를 계약에 넣는다. PDF 확인 절차와 제외 판정 근거(접수번호·URL 또는 로컬 식별자·시도 결과), 여러 판본 선택 우선순위를 ④에 명시하고 전체 후보 순서를 커밋한다. 결함을 나중에 찾았을 때는 원판 결과와 수정판 결과를 모두 보존한다.

## 기록만 할 것

### 8. [중요, 개발 분류의 한계] 측정 v2도 같은 숫자의 다른 빠진 행을 ‘보고됨’으로 돌린다

- **위치:** `eval/measure_documents.py:219-232`.
- **근거:** `classify`에 OpenDART `유동자산 당기=1,000`, `비유동자산 당기=1,000`, 제품 행 없음, 문제 `"유동자산 금액 '1,000'을 읽지 않았다"`를 넣자 **두 항목 모두** `status='reported'`였다. `units_confirmed`도 문서 안 다른 재무제표의 동일 단위 표기가 맞았다는 이유로, 해당 표가 정확한 OpenDART 대응이 없어도 `pdf_confirmed`를 허용하는 합성 사례가 나왔다(`dart_exact=1`인 첫 표, `pdf_confirmed=1`인 둘째 표). 이것은 공식 D4 채점기가 아니라 개발 분류기의 한계다.
- **제안:** 개발 수치를 인쇄 정답·공식 S2로 부르지 않는다. 같은 숫자의 경고는 행/기간을 연결하고, 단위 확인은 표 단위로 제한한다. 공식 점수는 위 1~4번을 고친 독립 정답과 채점으로 낸다.

### 9. [중요, 스캔 한계] Vision 계정명이 없거나 OCR이 세 자리만 읽은 줄은 칸 수준 근거가 약하다

- **위치:** `dart_review/documents/ai_reader.py:452-500, 525-537, 594-607, 627-639`; `docs/EVAL_CONTRACT_D4.ko.md:32-33, 99-103`.
- **근거:** 위 옛 사진 반례의 첫 칸은 계정명 토큰 없이도 `status='검사 통과'`, `evidence='OCR (숫자만, 계정명 미확인)'`이었다. `read_document`는 이후 재무제표 수준에 미확인 행 수를 적지만 칸은 표시하지 않는다. OCR 토큰 `'682'`만 있고 AI가 읽지 않은 합성 입력에서 `_report_unread_tokens`의 문제는 `[]`였고, `'1,682'`는 금액별 문제를 남겼다(기준이 숫자 네 자리). OCR 토큰이 전혀 없는 서로 다른 두 진짜 행을 모델이 `매출액 1,000`으로 연속 읽는 합성 입력은 `_ai_only_repeat` 때문에 한 행으로 합쳐졌다. 그 남은 행은 AI만 읽은 값으로 표시되지만 두 번째 누락 행을 특정하지는 못한다.
- **제안:** 이 선택을 스캔의 계정명 검증·누락 검출 한계로 보고한다. 스캔 L1·S2가 공식 문턱이 아니더라도, ‘검사 통과’가 이름까지 확인됐다는 뜻으로 읽히지 않게 칸 상태를 나누거나 미확인 표시를 붙인다. 세 자리 OCR 숫자 보고 여부는 주석 오탐과 함께 검토한다.

### 10. [중요, 다중 서버 조건] 새 서버가 살아 있는 다른 서버의 작업을 실패로 바꿀 수 있다

- **위치:** `dart_review/server.py:140-176`.
- **근거:** 임시 디렉터리의 `JobStore` A에서 합성 `%PDF-` 작업을 `running`으로 바꾸고 같은 디렉터리의 B에서 `abandon_unfinished()`를 호출하자 `before=running, abandoned=1, after=failed`였다. B가 재시작한 단일 프로세스인지 동시에 켠 둘째 프로세스인지 확인하는 잠금/소유권이 없다. 이전 삭제 경쟁과 삭제 실패 반례는 조건부 전이·`delete_failed` 상태로 수정됐고, 임의 `RuntimeError`의 원문도 `_SAFE_MESSAGES`에 맞지 않으면 숨겼다. 실제 동시 서버 실행은 시험하지 않았다.
- **제안:** 서버 데이터 디렉터리를 단일 인스턴스로 잠그거나 작업마다 실행 인스턴스/heartbeat를 기록해 죽은 작업만 버린다. 당장은 같은 저장소를 두 서버가 공유하지 않는다는 운영 조건을 명시한다.

### 11. [사소] 개발 보고서 후반부가 최종 사진 재측정과 모순된다

- **위치:** `eval/documents_2026-10-10_after-codex/REPORT.ko.md:5, 64-76, 101-115`.
- **근거:** 최종 제품 변경 `git diff 0d8f8ee..51fd837 -- dart_review/`은 사진 계정명 비교 네 줄이다. `photo_51fd837/ai.json` 직접 집계는 **246칸 중 확인 필요 95칸**, 2.4절도 95/246(39%)이라고 적는다. 그러나 5절은 ‘지금 69/246’, 6절은 ‘계정명 오타는 표시되지 않는다’, ‘확인 필요 28%’라고 단정한다. 그 수치는 2.2절의 **이전 제품** 기록이다.
- **제안:** 5·6절의 시점을 `0d8f8ee`로 명시하고 최종 제품 `51fd837`의 수치를 95/246으로 고친다. 2.2절의 원시 기록과 `review.json`의 과거 판정은 보존하고, 재측정 뒤 사용자 검토가 아직 없다는 점은 계속 표시한다.

## 핵심 반례의 최소 재현 명령

저장소 루트에서 실행한다. 아래 입력은 모두 임시 객체이며 실제 문서나 DB를 열지 않는다.

```bash
./.venv/bin/python - <<'PY'
from eval.d4_score import score
g = {'statements':[{'kind':'BS','title':'연결재무상태표','page':1}],
     'cells':[{'statement':'연결재무상태표','page':1,'label':name,'period':0,'printed':'1,000','value':1000}
              for name in ('유동자산','비유동자산')]}
def report(rows, problems):
    return {'statements':[{'title':'연결재무상태표','page':1,'problems':problems,
      'rows':[{'label':name,'values':[{'column':0,'value':value,'printed':str(value),
                                      'status':'검사 통과','page':1}]} for name,value in rows]}], 'problems':[]}
print('one warning, two omissions', score(g,report([], ["유동자산 당기 원본 금액 '1,000'을 읽지 않았다"]))['totals'])
print('row/period warning', score({'statements':g['statements'],'cells':g['cells'][:1]},
      report([],['유동자산 당기 칸을 읽지 못했다']))['totals'])
print('unmarked extra', score({'statements':g['statements'],'cells':g['cells'][:1]},
      report([('유동자산',1000),('주석 표 숫자',77)],[]))['totals'])
PY
```

관찰: 차례로 `missing=2,S2=0`; `missing=1,S2=1`; `not_in_gold=1,S1=L1=S2=0`이었다. 같은 제목·다른 쪽 두 표의 반례는 본문의 `gold_cells=4, correct=2, missing=2, S2=2`처럼 위 함수에 `statements`/`cells`를 두 쪽으로 늘려 확인했다.

```bash

from pathlib import Path

def line(label,a,b,y):

    return {'page':1,'words':words,'text':' '.join(w['text'] for w in words),
            'compact':''.join(w['text'] for w in words),'top':y,'bottom':y+8}
lines=[line('매출액','1,000','2,000',100),line('A계정','47','48',200),

     patch('eval.d4_gold.statements_of',return_value=[block]):

```

관찰: 정답에는 `매출액`과 `A계정`의 두 기간만 남고 `B계정` 두 칸은 없으며 `needs_mapping=[]`였다.
