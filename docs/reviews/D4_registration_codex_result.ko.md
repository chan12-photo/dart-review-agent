### 2. [중요] 평가 호출 실패가 공식 실행기의 최종 성공 코드에 반영되지 않는다

- **최소 수정:** 비정상 종료 건수·호출 이름·완료 상태를 `run.json`에 기록하고 하나라도 있으면 실행기 종료값을 비0으로 만든다. 계약상 필요하면 나머지 호출은 계속 실행해도 된다. 임시 합성 입력과 가짜 자식 종료값으로 성공·실패의 기록/최종 종료값을 테스트한다. 수정본을 ⑦의 실행 파일로 등록한다.

## ⑦·⑧ 판정 가능성과 직접 확인하지 못한 것

- 현재 `draft` 매핑표로는 공식 판정이 불가능한 것이 계약상 정상이다. 사용자 확인 뒤 10개 매핑표를 `confirmed`로 만들고, ⑦ 등록 명령에 고정 기록, 모집단·후보/다운로드 기록, 정답·확정 매핑표 10쌍, 스캔 대응표 30개, `documents.json`, `run_d4.py`, 공식 절차를 빠짐없이 포함해야 한다. R을 커밋·태그·push한 뒤 깨끗한 별도 체크아웃에서 `check`가 통과해야 한다. 이번에는 `register`·원격 태그 `check`를 실행하지 않았다.
- 매핑을 적용한 10개 문서는 모두 `unscorable=[]`이다. 실제 S1·L1·S2는 제품 실행 뒤에만 알 수 있지만, **모두 0이어도 위 중복 행 오판 반례를 배제할 수 없으므로 현재 계약만으로는 공식 합격을 신뢰하기 어렵다.** 정답 밖 제품 칸은 계약 4.5의 사람 판정이 끝나야 `official_ready`가 될 수 있다. 자식 종료값 0은 공식 합격이나 `official_ready=true`와 다르다.
- 당시 DART 첨부 화면, 원격 공시 원본, 매핑 결정 215건 전부의 독립 육안 대조, 스캔 30개 전체 재생성, 규칙·AI 제품의 실제 정확도는 확인하지 않았다. 이 보고서는 ⑧ 실행 승인이나 점수 예측이 아니다.
- 테스트: 처음에 없는 `tests.test_d4_scan`을 포함한 명령은 모듈 로더 오류가 났다. 실제 파일명을 확인한 뒤 `./.venv/bin/python -m unittest tests.test_client tests.test_d4_population tests.test_d4_run` **28개 통과**, `./.venv/bin/python -m unittest tests.test_d4_tools` **52개 통과**. 평가 PDF로 제품을 실행한 테스트는 없다.

**다음 순서:** 위 1~3을 해결하고 임시 테스트를 통과시킨다 → 문구 4·5를 바로잡는다 → 사용자가 매핑표를 확인한다 → ⑦ R 등록·태그 push를 별도 승인받는다 → ⑧도 별도 승인받은 뒤 실행한다. 여기서는 어느 단계도 자동 진행하지 않는다.
