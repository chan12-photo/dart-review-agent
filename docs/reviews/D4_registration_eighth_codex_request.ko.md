## 요청문

`AGENTS.md`를 따른다. 인증키, OpenDART API, Ollama, 네트워크는 쓰지 않고, 제품(`python -m dart_review extract`, `eval/d4_score.py --pdf`, `eval/d4_eval/run_d4.py`의 실제 실행)을 평가 문서에 **돌리지 않는다**. 추적 파일은 수정하지 말고, 결과는 `docs/reviews/D4_registration_eighth_codex_result.ko.md`에 저장해 줘. 결과에 로컬 홈 디렉터리의 절대 경로는 쓰지 말고 `~/`로 적어 줘. 칭찬은 필요 없다.

대상은 `537a6e7..HEAD`다. 7차 재검토 결과와 응답은 `docs/reviews/D4_registration_recheck_codex_{result,response}.ko.md`에 있다. 평가 문서 PDF(`~/Desktop/D4/`)는 읽기만 해도 된다.

기준은 같다. **등록한 대로 정직하게 실행하면 틀린 공식 결과(특히 거짓 `met`)가 나올 경로가 남았는가.** 계약 1.3의 신뢰 경계 밖은 범위 밖이다.

1. **실행 기록 관문** (`eval/d4_eval/official_d4.py run_gate`): 실패, 중단, 중복, 누락, 다른 문서 목록의 실행 기록에서 나온 보고서가 공식 판정 가능이 되는 경로가 남았는가. 재실행 폴더를 `--readers`로 고를 때 섞이는 경로가 있는가. 계약 7절의 "제품 실패는 다시 돌려 덮지 않는다"가 실행기·집계와 맞는가.
2. **위치 판정 형식** (`eval/d4_eval/position_check.py _verdict_count`와 판정 파일 검사): 사람이 틀렸다고 적었는데 0으로 읽히거나, 모양이 다른 파일이 조용히 받아들여지는 경로가 남았는가. 정답 밖 판정 파일(고정 채점기의 `check_verdicts`)도 집계에서 같은 정도로 막히는가.
3. **등록 자리 대조** (`fits_gold`, `verify`): 매핑표가 바뀐 뒤에도 공식 판정이 나오는 경로가 남았는가. ⑨의 대조가 순서를 보지 않는 것을 ⑦ 관문(`verify`)이 메우는가. 절차서 ⑦의 관문 위치가 맞는가(확정 → `verify` → 커밋 → `register`).
4. **절차서** (`docs/D4_RUN_PROCEDURE.ko.md`): 모든 명령 블록이 새 터미널에서 그대로 붙여 돌아가는가(`$PY`). 실제 점검·실행 없이 `--help`, `--dry-run`, `verify`로만 확인해 줘.
5. 7차 재검토의 나머지 확인(자리 66곳, 인쇄 순서, 개발 보고서, 채점기와의 일치)이 이번 수정으로 깨지지 않았는가. 고정 경로(`git diff 49c182b HEAD -- dart_review pyproject.toml eval/d4_{gold,score,candidates,preflight,scan}.py`)가 비어 있는가.

각 발견에 다음을 적어 줘.
- 심각도
- 위치
- 근거(명령과 결과, 합성 반례)
- 가장 작은 수정

"등록 전에 반드시 고칠 것"과 "보고서에 적을 것"을 나눠 주고, 등록 전에 고칠 것이 없으면 그렇다고 분명히 적어 줘.
