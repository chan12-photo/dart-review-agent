## 등록 전에 반드시 고칠 것

### 1. [중요] 예상 밖 실행 로그·실패 이름이 있어도 해당 묶음이 `met`이다

- **위치:** `eval/d4_eval/official_d4.py:67-104` (`run_gate`), 특히 76-103행.
- **근거:** 임시 `OfficialTests`의 정확한 `a.text.ai` 보고서, 완료된 `run.json`, 네 건의 정상 로그로 3.1은 `met`이다. 같은 임시 `run_log.jsonl` 끝에 `{"n":5,"name":"foreign.text.ai","exit":0}` 한 줄을 더하면 로그는 다섯 건인데도 `a.text.ai official_ready=True`, 3.1 `met`이다. 별도로 로그는 네 건 그대로 두고 `run.json.failed=[{"name":"foreign.text.ai","exit":2}]`, `succeeded=3`, `calls=4`로 바꾸어도 `a.text.ai official_ready=True`, 3.1 `met`이다. `run_gate`는 기대하는 이름의 로그 개수만 세고, 예상 밖 이름과 실패 목록의 이름이 실제 호출 집합에 속하는지는 보지 않는다. 실행 명령은 `./.venv/bin/python - <<'PY'`로 `tests.test_d4_official.OfficialTests` 임시 fixture를 만든 뒤 위 JSON을 바꾸고 `case.result()`를 호출했다. 제품 호출은 없었다.
- **영향과 경계:** 두 상태는 새 폴더를 만드는 현재 `run_d4.py`의 정상 출력이 아니다. 다만 기록을 복사하거나 합치는 실수로 이런 폴더가 생겼을 때, 관문이 주장하는 “정확히 이 실행의 호출만 성공”을 확인하지 못한다. 판정의 근거가 될 실행 기록 자체가 모순되어도 공식 `met`을 허용하는 경로다.
- **가장 작은 수정:** `run_log.jsonl`의 전체 이름 멀티셋이 계획된 호출 이름 멀티셋과 정확히 같고 총 건수가 `calls`와 같은지 검사한다. `failed`의 이름도 계획된 이름 안에 있고 중복이 없는지 확인하며, 각 이름의 로그 종료값과 성공/실패 목록이 일치하게 한다. 알 수 없는 로그 한 줄, 알 수 없는 실패 이름, 중복 실패 이름을 각각 합성 회귀 시험으로 막는다. 정상 로그와 한 방식만 고른 `--readers`는 계속 통과해야 한다.

### 2. [중요] 내용이 빈 잘못된 `verdicts` 형식이 조용히 통과한다

- **위치:** `eval/d4_eval/official_d4.py:117-126`; `eval/d4_eval/position_check.py:212-215`; 고정 채점기의 `eval/d4_score.py:131-148`.
- **근거:** 같은 임시 정확한 보고서에 `<이름>.extras.json` 또는 `<이름>.position.json`을 `{"verdicts":[]}`, `{"verdicts":""}`, `{"verdicts":false}`로 각각 저장했다. 여섯 경우 모두 `official_ready=True`, 3.1 `met`이었다. 코드의 `get("verdicts") or {}`가 거짓으로 평가되는 다른 자료형을 `{}`로 바꾼다. 이번 시험에서는 실제 판정이 필요한 칸이 없었으므로 **숫자 점수가 틀렸다는 반례는 아니다**. 다만 제공된 판정 파일의 형식이 틀려도 거부한다는 새 설명과 검사가 성립하지 않는다. 판정이 실제로 남아 있으면 이 입력만으로 `met`이 되지는 않는다.
- **가장 작은 수정:** 파일이 없을 때만 `{}`를 사용한다. 파일이 있으면 `verdicts`가 없을 경우를 허용할지 계약대로 명시하고, **있다면 빈 값이어도 반드시 객체인지 검사**한다. 정답 밖 판정과 위치 판정에 같은 경계를 적용하고 빈 배열·빈 문자열·`false`·정상 빈 객체의 회귀 시험을 추가한다. 고정 채점기 자체는 바꾸지 않고 공식 집계의 입력 검사에서 막을 수 있다.

## 보고서에 적을 것

- 위 1번은 **기록 오염 합성 반례**다. 현재 실행기가 정상 실행 중 그런 로그를 만든다는 증거는 없다. 수정 뒤에도 실행 폴더를 섞지 않는 운영 절차와 `--readers`의 폴더별 출처 기록은 유지해야 한다.
- 위 2번은 형식 계약의 구멍이며, 검토한 합성 사례에서는 점수나 공식 판정의 거짓 양성이 아니었다. 잘못된 판정 파일을 거부하는지와 숫자 판정이 옳은지는 별개의 검증이다.
- `verify`는 ⑦에서 **매핑표 확정 → PDF로 재생성한 자리와 비교 → 커밋 → register** 순서에 놓였다. 현재 초안에서 `the same: 66 places of 10 documents`가 나왔지만, 사용자 확인 뒤 매핑표가 바뀌면 다시 실행해야 한다. `fits_gold`의 ⑨ 검사는 자리 ID와 값·인쇄 글자·쪽의 모임을 비교하고, 행의 인쇄 순서 자체는 비교하지 않는다. 그 순서는 ⑦ `verify`의 전체 객체 비교가 맡는다. 이 작업에서 매핑표를 확정하거나 ⑦ 등록을 하지는 않았다.
