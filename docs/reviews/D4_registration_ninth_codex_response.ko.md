# D4 9차 검토(Codex, ⑦ 전)에 대한 응답 (2026-10-20)

- 대상: `docs/reviews/D4_registration_ninth_codex_result.ko.md` (기준 `4b1771d`). 결과 파일은 이 응답과 같은 커밋에 그대로 넣었다.
- **결론:** 등록 전에 고칠 1건과 보고서용 2건을 모두 고쳤다.
  - 새 시험은 고치기 전 코드에서 실패하고 지금 통과한다(옛 코드를 잠시 되돌려 확인).
  - 고정한 제품과 평가 도구 5개는 바꾸지 않았다. 제품을 평가 문서에 돌리지 않았다.
- **Codex가 확인해 준 것:** 8차의 실행 기록 모순은 막혔다. 정직한 실행 기록(모두 성공, 일부 실패, AI만 다시 돌림)을 너무 엄격하게 거부하는 경로는 없었다.
- **Claude의 실수:** 8차를 고치며 "파일이 없을 때만 판정 없음"이라고 썼다. 그런데 코드는 파일 존재를 내용(`None`)으로 판단해, 내용이 `null`인 파일을 없는 파일로 읽었다. 응답의 주장과 코드가 달랐다.

## 1. 등록 전에 고칠 것

| # | 처리 |
|---|---|
| 1 [중요] 내용이 `null`인 판정 파일이 "파일 없음" | 공식 집계는 판정 파일의 존재를 **경로**(`exists()`)로 정한다. 있으면 내용이 반드시 객체여야 한다. `position_check.py check --verdicts`도 주어진 파일의 내용이 객체가 아니면 거부한다. 시험: 정답 밖·위치 판정 파일 각각의 `null`이 `not official`이 된다. 파일이 없으면 지금처럼 판정 없음이다 |

## 2. 보고서에 적을 것 (고쳤다)

| # | 처리 |
|---|---|
| 2 [사소] `judgment_files_not_read`가 다른 방식의 파일을 빠뜨림 | 목록을 **이번 집계가 실제로 읽은 호출**의 판정 파일 이름 밖의 모든 파일로 좁혔다. 이름이 틀린 파일과 이번에 고르지 않은 방식의 파일이 모두 나온다. 시험 있음. 이 목록은 점수에 영향이 없다(읽지 않은 파일은 세지 않고, 그 호출은 판정 대기로 남는다) |
| 3 [사소] 판정이 없는 빈 파일의 보고서 해시를 보지 않음 | 엄격한 쪽을 택했다. 판정 파일은 **있으면** 판정이 없어도 그 보고서의 해시와 판정자를 적어야 한다. 다른 보고서의 빈 파일, 해시나 판정자가 없는 빈 파일(`{}`, `{"verdicts": {}}`)을 거부한다. 정답 밖 판정 파일은 고정 채점기가 빈 판정일 때 해시를 보지 않으므로 공식 집계가 앞에서 검사한다. 위치 판정 파일은 `position_check.check`가 직접 검사한다. 판정할 것이 없으면 파일을 만들지 않아도 된다고 절차서에 적었다 |
