# D4 9차 검토 결과: 8차 수정만 (⑦ 전)

- 검토일: 2026-10-20. 대상: `f92a91a..4b1771d`.
- **결론: ⑦ 등록 전, 판정 파일의 `null` 한 경우를 고쳐야 한다.** 8차의 실행 기록 반례와 `verdicts` 내부의 잘못된 빈 형식은 막혔다. 정상 실행기가 쓴 성공·부분 실패·AI만 재실행 기록도 새 관문을 통과했다. 그러나 판정 파일 **전체가 JSON `null`**이면 파일이 없는 것으로 읽혀 공식 `met`까지 나온다. 이 시험에서 판정할 칸은 없었으므로 숫자 오판을 재현했다는 뜻은 아니다. 파일이 있으면 객체여야 한다는 계약과 응답의 주장이 깨진다.
- 인증키, OpenDART API, Ollama, 네트워크는 사용하지 않았다. 평가 PDF는 `verify`와 비실행 `--dry-run`에서만 읽었다. 제품 추출·PDF 채점·실제 D4 실행은 하지 않았고, 이 결과 파일 외의 추적 파일은 수정하지 않았다.

## 등록 전에 반드시 고칠 것

### 1. [중요] 판정 파일 전체의 JSON `null`이 ‘파일 없음’으로 처리된다

- **위치:** `eval/d4_eval/official_d4.py:70-72,143-165` (`_json`, `call`), `eval/d4_eval/position_check.py:211-217`.
- **근거:** `tests.test_d4_official.Fixture`의 임시 정확한 `a.text.ai` 보고서와 정상 실행 기록을 사용했다. `a.text.ai.extras.json` 또는 `a.text.ai.position.json`의 **파일 내용**을 각각 문자 그대로 `null`로 저장하고 `case.result()`를 호출했다. 양쪽 모두 파일은 존재하고 출력의 `judgments`에 SHA-256까지 남는데 `official_ready=True`, 3.1 `met`이었다. `_json`은 파일이 없을 때도, 존재하는 파일을 `json.loads("null")`로 읽을 때도 `None`을 돌려준다. `call`은 이 둘을 구별하지 않아 내부 객체 형식 검사를 건너뛴다. 반면 `{"verdicts":null}`은 새 검사에서 거부된다. 이 합성 시험은 제품을 호출하지 않았다.
- **영향과 경계:** 실제로 판정할 칸이 남아 있다면 파일이 무시되어 해당 호출은 판정 대기 상태가 된다. 위 `met`은 판정할 칸이 없는 경우의 **잘못된 파일 수용**이며, 틀린 금액을 맞는 금액으로 바꾼 사례는 아니다. 그래도 계약 4.6과 절차서 ⑨의 ‘존재하는 판정 파일은 객체, `null` 거부’라는 입력 검사가 성립하지 않는다.
- **가장 작은 수정:** `_json`의 `None`만으로 존재 여부를 판단하지 말고, 각 판정 경로의 `exists()`를 별도로 사용한다. 파일이 있으면 `json.loads` 결과가 반드시 객체인지 검사한다. 정답 밖·위치 판정 파일 각각에 대해 최상위 `null`은 `not official`, 파일 없음과 정상 빈 객체는 기존처럼 처리하는 합성 회귀 시험을 추가한다.

## 보고서에 적을 것

### 2. [사소] `judgment_files_not_read`는 실제 ‘읽지 않은 파일’ 전부를 뜻하지 않는다

- **위치:** `eval/d4_eval/official_d4.py:228-233`.
- **근거:** 같은 임시 fixture는 `readers=["ai"]`인 실행 폴더다. 판정 폴더에 `a.text.rules.extras.json`을 넣고 집계하니 파일은 존재하지만 `judgment_files_not_read=[]`, AI 3.1은 `met`이었다. `known` 집합이 이번 실행·이번 선택 방식이 아니라 문서 목록의 **규칙·AI 양쪽** 이름을 모두 담기 때문이다. 이 파일은 현재 호출에서 읽지 않았다.
- **영향:** 공식 점수에는 영향이 없다. 절차서처럼 실행 폴더마다 판정 폴더를 나누면 다른 방식의 파일이 섞일 가능성도 작다. 다만 필드 이름과 ‘어느 호출의 이름도 아닌 파일’이라는 설명을 실제 검사 범위에 맞추거나, 검사 대상을 이 실행에서 실제 선택한 호출의 판정 파일로 좁히는 것이 정확하다. 파일 이름이 잘못됐지만 우연히 다른 방식의 정상 이름인 경우를 안내하지 못한다.

### 3. [사소] 판정이 없는 빈 객체 파일의 보고서 해시 검사는 계약 문구와 구별해야 한다

- **위치:** `eval/d4_score.py:131-140`, `eval/d4_eval/position_check.py:216-220`; `docs/D4_RUN_PROCEDURE.ko.md:111-117`.
- **근거:** 임시 판정 파일을 `{"report_sha256":"other","judged_by":"tester","verdicts":{}}`로 두면 정답 밖·위치 판정 모두 `official_ready=True`, 3.1 `met`이었다. 두 검사 모두 판정 항목이 비면 해시 확인 전 반환·통과한다. 판정 항목이 있으면 다른 해시를 거부한다.
- **영향·제안:** 빈 파일이 사실상 ‘판정 없음’이어서 이 반례에는 숫자 영향이 없다. 절차서는 두 파일 모두 현재 보고서 SHA-256을 적으라고 한다. 빈 판정 파일도 보관한다면 해시·판정자 검사를 할지, 빈 파일은 아무 판정도 없는 선택적 파일로 볼지 계약·절차서·시험의 표현을 맞춘다. 고정 채점기를 바꿀 필요는 없다.
