- **위치:** `eval/d4_score.py:53-81, 113-148`; `docs/EVAL_CONTRACT_D4.ko.md:102-109`.
- **근거:** `./.venv/bin/python - <<'PY'`에서 합성 정답 `매출액` 당기·전기 모두 `1,000`, 제품 칸 없음, 문제 `1쪽 '매출액' 줄: 원본의 금액 '1,000'를 AI가 읽지 않았다`를 `score()`에 넣자 `missing=2, S2=0`이었다. 같은 행·금액이 두 기간에 있으므로 어느 기간을 가리키는지 알 수 없다. `유동자산` 1쪽 당기 누락에 `9쪽 유동자산 당기 칸을 읽지 못했다` 또는 `유동자산 당기 값은 정상 확인했다`를 넣어도 각각 `S2=0`이었다. `pointed()`의 행+기간 부분 문자열 분기는 쪽과 실제 누락/오류 의미를 보지 않는다. `pointers()`의 규칙 방식 표기 `1쪽 '47' (기타(손실))`는 행을 `기타(손실`로 잘라, 정확한 경고도 놓칠 수 있다.

## 주요 반례의 재현 입력

다음은 저장소 루트에서 실행한 **합성 객체**의 축약본이다. 실제 PDF·제품 DB를 읽지 않는다.

```bash
./.venv/bin/python - <<'PY'
from eval.d4_score import score
s = {'id':'BS@1','kind':'BS','title':'연결재무상태표','page':1}
g = {'statements':[s], 'cells':[]}
def row(label, n):
    return {'label':label,'values':[{'column':0,'printed':str(n),'value':n,'status':'검사 통과'}]}
r = {'statements':[{'title':s['title'],'page':1,'rows':[row('주석 표',77)],'problems':[]}]}
k = 'BS@1|주석 표|0|77'
print('invalid verdict', {x:score(g,r,{k:'pending'})['totals'][x]
                         for x in ('not_in_gold','unjudged_extras','S1','complete')})
r['statements'].append({'title':'연결현금흐름표','page':2,'rows':[row('가짜행',999)],'problems':[]})
print('unmatched table', {x:score(g,r,{k:'ok'})['totals'][x]
                          for x in ('not_in_gold','product_statements_not_in_gold','complete')})
PY
```

출력: `invalid verdict {'not_in_gold': 1, 'unjudged_extras': 0, 'S1': 0, 'complete': True}`; `unmatched table {'not_in_gold': 1, 'product_statements_not_in_gold': ['연결현금흐름표'], 'complete': True}`. 본문 2번의 `not_in_gold=0`은 **첫 표에 주석 표 행도 없는 별도 입력**이다. 위 두 번째 출력은 첫 표의 행을 그대로 둔 독립 재현으로, 핵심인 짝 없는 표와 `complete=true`가 같다.
