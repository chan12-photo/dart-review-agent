# D5 평가 등록 전 Codex 검토 결과

- 검토일: 2026-10-21
- 범위: `git diff d5-frozen..HEAD`, D5 계약 6판, 등록·실행·판정 절차, 후보 기록, 정답·매핑 초안, 위치 검사 자리, 문서 목록과 스캔 대응표
- 제한 준수: 인증키·OpenDART API·Ollama·네트워크를 쓰지 않았다. 제품 추출, `eval/d4_score.py --pdf`, `run_d4.py` 실제 실행은 하지 않았다. 실행기의 `--dry-run`과 정답·자리 생성기의 읽기/검사 경로만 썼다.

## 결론

**현재 상태로는 ⑦ 등록을 보류해야 한다.** 등록 전에 고칠 중요 사항이 2개 있다.

1. `draft_mappings.py`가 한 줄의 이웃한 두 금액을 붙여 검색해 실제로 인쇄된 금액을 “인쇄 없음”으로 판정한다. 현재 `ignore` 결정 7개의 결론 자체는 맞지만 근거가 거짓이고, 같은 규칙은 정답 생성기가 빠뜨린 인쇄 행을 그대로 `ignore`할 수 있다.
2. `build_places.py`의 감긴 계정명 대체 경로가 계약의 두 자리로 제한되지 않고, 위·금액·아래 줄 사이의 거리도 확인하지 않는다. 현재 등록 JSON의 두 자리는 맞지만, 매핑 결정이 바뀌어 자리를 다시 만들 때 다른 곳의 세 줄을 한 행으로 받아들일 수 있다.

위 둘을 막은 뒤에는 현재 자료에서 등록을 막을 실제 정답 칸·자리·문서 목록·해시 오류를 찾지 못했다. 후보 수집의 멈춤 시점 등 되돌릴 수 없는 절차 차이는 아래 “기록할 것”에 남긴다.

## 등록 전에 반드시 고칠 것

### 1. 실제 인쇄 금액 7개를 “인쇄 없음”으로 기록하고, 빠진 인쇄 행을 `ignore`할 수 있다

- **심각도:** 중요
- **위치:**
  - `eval/d5_eval/draft_mappings.py:83-84`, `:121-144`
  - `eval/d5_eval/gold/20_01867758.mapping.json:23,27`
  - `eval/d5_eval/gold/26_01101041.mapping.json:15,19`
  - `eval/d5_eval/gold/28_01160363.mapping.json:15`
  - `eval/d5_eval/gold/31_00106881.mapping.json:7,11`
  - `eval/d5_eval/REVIEW_GUIDE.ko.md` 5절의 “인쇄 없음 49개 / 두 번째 저장 15개”
- **원인:** `_printed_on`은 공백을 모두 지운 `line["compact"]`에서 숫자 경계를 찾는다. 예를 들어 인쇄 줄 `계속사업 기본 및 희석 주당순이익 1,210 707`은 `...1,210707`이 되어 `1,210`도 `707`도 독립된 금액으로 잡히지 않는다.
- **근거(명령과 결과):** PDF 글자 층의 금액 **단어**를 기준으로 모든 `dart_only`/`ignore` 중 “어디에도 인쇄되지 않았다”는 항목을 다시 검사했다.

  ```bash
  .venv/bin/python - <<'PY'
  # lines_of의 각 word를 금액 단위로 비교하고, 저장된 note가 "어디에도"라고 한 항목만 출력
  PY
  ```

  실제 출력은 다음 7개였다.

  ```text
  20_01867758 n5  1,210  -> 12쪽 "... 주당순이익 1,210 707"
  20_01867758 n6  707    -> 같은 줄
  26_01101041 n3  2,663,671,300 -> 7쪽 "자본금 ... 2,663,671,300 2,663,671,300"
  26_01101041 n4  2,663,671,300 -> 같은 줄
  28_01160363 n3  3,511,370,550 -> 11쪽 "순확정급여제도의 재측정요소 ..."
  31_00106881 n1  37,928,403,107 -> 7쪽 "자 본 총 계 ..."
  31_00106881 n2  37,860,333,783 -> 같은 줄
  ```

  합성 반례에서도 실제 인쇄 줄 `새 계정 1,210 707`을 넣자 `decide`는 다음처럼 잘못 `ignore`했다.

  ```text
  {'decision': 'ignore', 'note': "... 1쪽 어디에도 '1,210'가 인쇄돼 있지 않다 ..."}
  ```

  이 경로는 정답 생성기가 어떤 인쇄 행을 빠뜨렸을 때 그 행의 OpenDART 값까지 `ignore`하여, 제품이 같은 행을 빠뜨려도 드러나지 않게 할 수 있다.
- **현재 자료에 미친 영향:** 위 7개는 모두 같은 재무제표·기간·값의 인쇄 정답 칸이 이미 있는 줄이었다. 따라서 일곱 `ignore` 결정 자체는 맞고 정답 칸 수 2,270도 바뀌지 않는다. 다만 note와 확인 안내의 분류가 틀렸다. 올바른 분류는 `ignore` 66개 중 **인쇄 없음 42개, 이미 정답 칸인 인쇄 줄 22개, 차바이오텍 명시 결정 2개**다.
- **가장 작은 수정:** `_printed_on`이 `line["compact"]`가 아니라 공백이 보존된 `line["text"]` 또는 `line["words"]`의 금액 토큰을 검사하게 한다. 그 상태를 메모리에서 적용해 145개를 다시 계산했을 때 **note를 뺀 결정·추가 칸은 하나도 바뀌지 않았다.** `--replace-drafts`로 초안을 다시 만들고 확인 안내의 49/15를 42/22로 고친 뒤 사용자가 수정된 근거를 확인한다. 결정은 그대로이므로 이 수정만으로 자리를 다시 만들 필요는 없지만, ⑦의 `build_places.py --check` 관문은 다시 통과시킨다.

### 2. 감긴 계정명 대체 경로가 계약의 두 자리를 넘어, 멀리 떨어진 줄도 한 행으로 받는다

- **심각도:** 중요
- **위치:** `eval/d5_eval/build_places.py:34-60`, `:75-86`; 계약 11.1절(`docs/EVAL_CONTRACT_D5.ko.md:182-191`)
- **원인:**
  - 계약은 차바이오텍의 정확한 당기·전기 두 자리만 대체 대상으로 정했지만, 코드는 어느 문서·어느 자리든 고정 빌더 오류 문자열에 `0 printed lines of that label`이 들어가면 대체 경로를 쓴다.
  - 대체 경로는 금액 줄의 바로 앞·뒤 배열 원소만 볼 뿐, 위 줄의 `bottom`과 금액 줄의 `top`, 금액 줄의 `bottom`과 아래 줄의 `top` 사이 거리를 검사하지 않는다.
- **근거(명령과 결과):** 위·금액·아래 줄의 `top`을 각각 1, 100, 200으로 둔 합성 입력도 `_fallback`이 정상 행으로 반환했다.

  ```text
  {'rows': [{'page': 1, 'top': 100, 'label': 'WrappedLabel',
             'printed': '1,000', 'value': 1000}]}
  ["1/100: 'Wrapped' + '1,000 2,000' + 'Label'"]
  ```

  즉 중간에 다른 텍스트 줄이 없기만 하면 시각적으로 한 행이 아닌 세 줄도 결합할 수 있다. 매핑 결정을 바꿔 새 중복 자리가 생긴 뒤 재생성할 때 잘못된 인쇄 순서를 등록할 경로다.
- **현재 자료에 미친 영향:** 현재 두 자리는 직접 렌더링과 좌표로 확인했다. 차바이오텍 PDF 8쪽의 두 행은 각각 `기타포괄손익-공정가치측정 금융자` / 금액 / `산`이고, 두 경계의 세로 간격은 모두 -1.0pt(글자 상자가 약간 겹침)였다. 값과 순서도 등록 JSON의 242.0, 479.0과 맞는다. 현재 `duplicate_places.json` 자체에는 오류가 없다.
- **가장 작은 수정:** 대체 경로를 다음 정확한 두 id로 허용 목록화하고, 그 밖의 `0 printed lines...`는 다시 예외로 멈춘다.
  - `연결재무상태표@8|기타포괄손익-공정가치측정금융자산|0`
  - `연결재무상태표@8|기타포괄손익-공정가치측정금융자산|1`

  또한 정답 생성기의 감긴 계정명 규칙처럼 위·금액·아래 줄이 같은 쪽에서 실제로 맞닿는지(예: 각 간격 4pt 이하) 검사한다. 수정 뒤 현재 파일에 대해 `build_places.py --check`가 계속 `the same: 49 places (2 by the wrapped-label fallback)`를 내야 한다. 고정 도구 T는 바꿀 필요가 없다.
