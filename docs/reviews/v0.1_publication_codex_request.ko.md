## 요청문

`AGENTS.md`를 따른다. 인증키, OpenDART API, Ollama는 쓰지 않는다. 3-1 봉인 평가는 끝났으므로 `eval/sealed_3-1/`의 기록과 로컬 캐시는 읽어도 된다. 다만 3-1 질문으로 모델을 다시 돌리거나 다시 채점해서 공식 결과를 바꾸지 않는다.

추적 파일은 수정하지 말고, 결과는 `docs/reviews/v0.1_publication_codex_result.ko.md`에 저장해 줘. 칭찬은 필요 없다. 틀렸거나, 근거가 약하거나, 결과를 실제보다 좋게 보이게 하는 것만 적어 줘. 발견마다 다음을 적어 줘.
- 심각도(치명/중요/사소)
- 위치(파일:줄)
- 근거(명령과 결과)
- 제안

그리고 "공개 전에 고칠 것"과 "기록만 할 것"을 나눠 줘.

대상은 `e44c58b..HEAD`의 변경이다. 특히 `README.md`, `README.ko.md`, `demo/README.md`, `docs/PUBLICATION_CHECK.ko.md`, `.github/workflows/ci.yml`, `scripts/check_history_safety.py`를 봐 줘.

### Part A. README의 주장과 결과 파일 대조 (가장 중요)

1. README 두 개의 모든 숫자와 주장을 원 기록과 대조해 줘. 원 기록은 `eval/sealed_3-1/REPORT.md`, `judge_report.json`, `runs/*/final.json`, `runs/*/summary.json`, `eval/feasibility_2026-10-07/REPORT.md`, `docs/DATA_NOTES.ko.md`다. 대상은 다음과 같다.
   - 결과표: 방식별 정답 수, 거절·되묻기 수, 틀린 수치 답, 그 밖의 실패, 모델 시간
   - 제품 기준 네 가지의 값
   - "95% 신뢰 상한 약 13%"
   - 실패 문항 ID와 그 이유
   - "LLM이 보탠 것 0건"
   - 함정 테스트 "11개 중 11개"
   - Codex 검토 "다섯 번"
   - "v0.1의 `dart_review/`는 P(`c182075`)와 같다"(`git diff c182075 HEAD -- dart_review`)
2. 한국어판과 영어판이 같은 내용을 말하는가. 한쪽에만 있거나 뜻이 달라진 주장이 있는가.
3. "할 수 있는 것" 표의 예시 질문을 `--no-model --cache cache --offline --reference-date 2026-10-08`로 돌려서, 표에 적은 답 종류와 같은지 확인해 줘.
4. 결과를 좋게 보이게 하는 표현이 있는가. 예를 들면 다음과 같다.
   - 공식 판정 "기준 미달"이 묻히는 배치
   - "틀린 수치 답 0"을 일반적인 정확도로 읽히게 하는 문장
   - 쉬운 질문 분포나 작성자 정보의 누락

### Part B. 공개 안전과 데이터

1. 다음 두 명령을 돌리고, 두 스크립트가 놓칠 수 있는 유형이 있는지 봐 줘(예: 인코딩된 키, 바이너리 파일, 경로 이름).
   - `DART_API_KEY_FILE=/nonexistent python3 scripts/check_public_safety.py`
   - `DART_API_KEY_FILE=/nonexistent python3 scripts/check_history_safety.py`
2. `docs/PUBLICATION_CHECK.ko.md` 3절의 데이터 목록이 실제 추적 파일과 맞는가. 원본 응답 전체(보고서당 수백 행)나 corpCode.xml 원본이 들어간 파일은 없는가.
3. 약관 해석(2절)에서 과하게 단정한 부분이 있는가.
4. 공개하면 안 되는 개인정보나 로컬 정보가 있는가. 사용자 원본 질문 파일의 위치처럼 문서에 남은 로컬 경로가 대상이다.

## 이미 알고 있는 것 (다시 적지 않아도 됨)

- 공식 판정은 기준 미달이다. 채점기와 제품의 해석 연도 불일치는 다음 평가부터 맞춘다.
- 값 조회 답의 "참고:" 줄은 반말이고, 나머지 문장은 존댓말이다.
- 연도 없는 값 조회에서 계정이 모호하면 "어느 것을 **비교**할까요?"라고 묻는다.
- 테스트 하나가 표준 출력에 JSON을 찍는다.
- 위의 세 가지는 공개 뒤 v0.1.x에서 고친다. 제품을 평가한 P와 같게 두려는 것이다.
