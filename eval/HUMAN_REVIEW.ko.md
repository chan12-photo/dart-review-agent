# 본문 검토 기준 (모델 실행 전에 고정)

- 고정: 2026-10-07, Claude 작성. **1-5 모델 실행 전에 커밋한다.** 실행 뒤에 기준을 바꾸면, 바꾼 이유와 바꾸기 전후의 점수를 모두 보고한다.
- 근거: Codex 1-5 검토 E3. 자동 채점은 구조화 칸과 숫자의 근거만 본다. 사용자에게 보이는 문장이 맞는 뜻인지는 사람이 이 기준으로 본다.
- 판정 순서: **자동 통과**(`automatic_passed`)이고 **본문 검토 통과**(`body_ok`)인 문항만 **최종 통과**(`reviewed_passed`)다. 자동 점수 원본은 그대로 보존하고 함께 보고한다.
- 검토자: Claude가 1차로 판정하고, 사용자가 확인한다. 의견이 다르면 사용자의 판정을 따르고 두 판정을 모두 기록한다. 기준에 없는 이유로 통과·실패를 정하지 않는다.
- 검토 대상: 자동 통과 여부와 관계없이 **모든 문항**의 본문을 본다. 자동 실패 문항도 본문 문제를 기록한다(원인 분석용).
- 숫자 표기의 오탐 정정: 자동 채점기가 처리하지 못한 표기(예: `1천2백억`)를 근거 없는 숫자로 센 경우에만, 사람이 그 숫자가 도구 결과의 값을 바르게 쓴 것인지 확인해 `numbers_override`로 정정할 수 있다. 원래 자동 점수와 정정 이유를 함께 남긴다. 반올림·버림 규칙(EVAL_DESIGN 4절)에 맞지 않는 숫자는 정정하지 않는다.

## 모든 문항 공통 (하나라도 어기면 본문 실패)

1. **대상:** 본문이 말하는 회사·계정·기준(연결/별도)이 정답과 같다.
2. **기간:** 본문이 말하는 연도와 기간의 종류(3개월 / 누적 / 시점, 몇 월 말)가 정답과 같다.
3. **역할과 방향:** 숫자를 올바른 기간에 붙였고(올해 값과 작년 값을 바꾸지 않음), 증가·감소·흑자 전환 등 방향이 정답과 같다.
4. **상태에 맞는 설명:**
   - `확인 필요`: 확인이 필요한 이유를 도구가 관찰한 범위로 말한다. "기준이 실제로 바뀌었다"처럼 단정하지 않는다.
   - `비교 불가`: 도구가 준 실제 이유를 말한다(예: 현금흐름표는 누적만 제공). 서버 장애나 데이터 부재 같은 다른 이유로 바꾸지 않는다.
   - `데이터 없음`: 해당 연도 자료를 제공하지 않는다는 뜻으로 말한다. 회사가 없다거나 오류라고 말하지 않는다.
   - `되묻기`: 본문에서 한쪽 계정으로 답을 확정하지 않고 숫자를 내놓지 않는다.
   - `나란히 표시`: 차이를 시간 변화(증가·성장)로 말하지 않는다.
5. **단정 금지:** 도구 결과에 없는 원인이나 사실을 사실처럼 말하지 않는다(예: "차이는 모두 자회사 매출 때문", "회계 기준이 바뀐 것이 확실"). 추정이면 추정이라고 밝혀야 한다.

본문이 짧아 내용이 부족한 것(예: "확인했습니다.")은 1~4번 중 해당하는 내용을 말하지 않은 것이므로 실패다.

## 기록 방법

`eval/run_eval.py --out <폴더>`가 만드는 `review_sheet.md`를 읽고, 같은 폴더의 `human_review.json`에 문항마다 `body_ok`(true/false)와 `note`(실패 이유는 위 번호로)를 적는다. 그다음 `python eval/finalize.py <폴더>`가 최종 점수를 만든다.
