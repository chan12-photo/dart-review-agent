### 2.3 독립 정답과의 대조 (D4 도구 시험)

### 2.4 사진 PDF 재측정: 계정명 오타 표시 (`51fd837`, `photo_51fd837/`)

2.2에서 표시되지 않은 같은 계정의 계정명 오타 3칸을 고쳤다. 사진 경로에서 Vision이 읽은 계정명과 **같을 때만** 계정명을 확인한 것으로 보고, 비슷하지만 다르면 "계정명 표기가 OCR과 조금 다르다 (오타일 수 있다)"로 표시한다. 계정명은 고치지 않는다. 이 변경은 사진 경로에만 있어서(`0d8f8ee..51fd837`의 `dart_review/` 차이는 그 4줄뿐) 사진 PDF만 다시 쟀다.

| | 2.2 (`0d8f8ee`) | 재측정 (`51fd837`) |
|---|---|---|
| 칸 | 246 | 246 |
| 확인 필요 | 69 (28%) | **95 (39%)** |
| 같은 계정의 계정명 오타, 표시 안 됨 | 3 | **0** |
| 틀린 값, 표시 안 됨 | 0 | 0 |

- **대가:** 새 표시의 대부분은 오타가 아니라 Vision이 계정명을 잘못 읽은 경우다. 사진 1~2쪽에서 새 표시 16칸 가운데 실제 모델 오타는 2칸("총당부채")이었고, 14칸은 Vision의 오독이었다("우형자산", "매입채우", "법인세비용차강전순이익" 등). 확인할 양이 늘어난 대신 표시 없이 지나가는 계정명 오류를 막았다.
- 정확도를 높일 다음 후보(이번에는 하지 않음): 두 읽기 가운데 실제 계정명 목록에 있는 쪽을 보는 방법. 같은 사진으로 다듬으면 과적합이 되므로 D4 재검토 뒤에 정한다.

## 6. 남은 약점

- **사진의 계정명 오타:** 같은 계정의 오타(유사도 0.75 이상)는 표시되지 않는다. D4 계약(4.3)은 계정명을 글자로 비교하므로 이런 칸은 L1에 들어간다.
- **사진의 띠 실패:** 모델이 출력 한도 안에 띠를 못 읽으면 "한 부분을 읽지 못했다"만 남고, 그 띠의 숫자 가운데 OCR이 읽은 것만 금액별로 보고된다.
- **사진의 1~2자리 금액**은 받지 않는다(주석 번호와 구분할 텍스트 층이 없다).
- 사진의 "확인 필요"가 28%다. 사람이 확인할 양이 많다.
- 이 측정은 개발 문서다. 정답 생성기와 제품 모두 이 문서들로 다듬었으므로, 2.3의 일치는 정확성의 근거가 아니다.
