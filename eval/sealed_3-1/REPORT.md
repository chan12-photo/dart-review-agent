## 3. 무엇을 알게 됐나 (냉정하게)

1. **제품은 틀린 수치 답을 내지 않았다.**
   - 23개 수치 질문 가운데 22개를 맞게 답했다. 1개는 틀린 답 대신 되물었다. 거절·되묻기 13개도 모두 맞았다.
   - 다만 0건은 이 36문항에서 본 관찰이다. 23개를 모두 답하고 0건이어도 95% 신뢰 상한은 약 12%이고, 실제로 답한 수치 질문은 22개다.
2. **이 질문들에서는 키워드 규칙만으로 23/23을 맞혔다.** 처음 보는 회사와 사용자가 쓴 질문에서도 규칙이 모든 질문을 맞게 읽었다.
3. **이번 평가에서 LLM은 답을 늘리지 못했고 비용만 더했다.**
   - "규칙 오답 / 모델 정답"과 "막은 오답"이 모두 0이다.
   - 교차 확인은 모델 오독(U07) 때문에 정답 하나를 잃었고, 모델 시간 약 8.7분을 더 썼다.
   - **이 36문항 기준으로 "LLM이 필요하다"는 근거는 없다.**
4. **모델 혼자 쓰면 위험하다는 근거는 나왔다.**
   - 모델만 방식은 진짜 오독 둘(C06 시점→3개월, U07 매출→시점)로 정답이 있는 질문을 거절했다.
   - U12에서는 거절 이유를 틀리게 말했다("회사 여러 개"인데 "다루지 않는 회사").
   - 교차 확인은 이런 오독이 답으로 나가지 않게 막는 구조다. 다만 이번에는 규칙이 이미 맞았기 때문에 막을 오답이 없었다.
5. **온도 0인데도 모델 출력이 실행마다 달랐다.** C06은 두 실행에서 요청 바이트가 같았다. 그런데 교차 확인 실행에서는 맞게(시점), 모델만 실행에서는 틀리게(3개월) 읽었다. 단일 실행 결과를 모델의 고정된 성질로 보면 안 된다.
6. **질문 난도가 낮았다.** 수치 질문 23개는 대부분 2024~2026년 단순 조회·비교였다. 2022~2023년 비교, 부호 전환, 계정ID 오표기 같은 어려운 유형이 없었다(Codex 2차 검토가 미리 지적함). 데이터를 보지 않고 질문을 쓴 결과다. 그래서 규칙이 모두 맞힌 것은 "규칙이 충분히 강하다"는 증거라기보다 "이 질문들이 규칙 범위 안에 있었다"는 뜻에 가깝다.
